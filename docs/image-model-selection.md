# 参考图模型选型（2026-09-13）

> 当前默认已按用户要求简化为 Klein 4B Distilled 生成白底人物、完整场景、白底道具，三张图直接进入 H3。下文 Base 合成与编辑比较保留为可选能力研究，不加入当前默认链。最新调用方式见 [白底三参考工作流](three-white-reference-workflow.md)。

目标：在 RTX 5080 16GB / 48GB RAM 上，为 H3 制作人物母版和前/侧/背三视图、场景、道具、首帧。优先级依次为：可本地运行且许可明确、参考编辑能力、身份/服装保持、构图控制、与现有 ComfyUI 共用环境、实际生成成本。不能只用文生图排行榜判断参考编辑质量。

## 候选与取舍

| 候选 | 已核实的能力和限制 | 本项目判断 |
|---|---|---|
| FLUX.2 Klein 4B（Distilled / Base） | 同一架构支持文生图、多图编辑；4B 为 Apache 2.0；快速版 4 步，Base 可使用更长采样与 CFG。ComfyUI 已原生支持。 | 优先本机验证。一个较小模型即可覆盖整条参考图链；比较快速版和 Base 后选择默认值。 |
| FLUX.2 Klein 9B | 多图编辑，规模更大；官方为非商业许可，且显存负担高于 4B。 | 不作为本次“开源、可复用、本地 16GB”默认。不能因此推断它质量差。 |
| Qwen-Image-2512 + Qwen-Image-Edit-2511 | 2512 是文生图权重；Edit 2511 为 20B、Apache 2.0，官方强调角色保持、视角和工业设计改进。 | 高价值备选，但需要较大的生成/编辑组件与卸载管理。本轮未安装、未实测其画质，不能宣称已在质量上击败它。 |
| Z-Image / Turbo | 6B 文生图；核查时官方模型表仍将 Omni-Base / Edit 下载列为 To be released。 | 场景/道具初稿有价值，但已发布文生图权重不能直接替代有参考条件的多视角编辑。 |
| FLUX.1 Kontext / 大型 FLUX.2 dev | 可参考编辑，但有额外规模、许可及部署取舍。 | 当前任务有更小的统一生成/编辑模型可先验证，不为“模型更大”增加维护复杂度。 |

这是一项面向本机和任务的工程选择，不是所有模型、风格、量化方式的全球最优证明。文档会明确哪些是来源信息、哪些是本机观察；不把厂商宣传的 5090 用时当作本机速度。

## 参考来源

- [BFL 模型与许可对照](https://bfl.ai/models/flux-2-klein)：4B Apache 2.0；9B 非商业；Base / Distilled 区别。
- [BFL 官方代码](https://github.com/black-forest-labs/flux2)：生成/编辑统一实现与各权重说明。
- [ComfyUI 原生 Klein 文档](https://docs.comfy.org/tutorials/flux/flux-2-klein)：CLIP 类型 flux2、Flux2 latent/scheduler、模型与 VAE 的配套。仅参考接口；本项目独立构建平铺图和阶段编排，没有直接运行下载来的完整工作流。
- [Qwen Edit 2511 模型卡](https://huggingface.co/Qwen/Qwen-Image-Edit-2511)：参考编辑、角色保持、视角、20B 与 Apache 2.0。
- [Qwen Image 2512](https://huggingface.co/Qwen/Qwen-Image-2512)：文生图版本。新模型发布消息不等同于开放了可下载权重，本轮不使用托管 API。
- [Z-Image 官方仓库](https://github.com/Tongyi-MAI/Z-Image)：模型表和实际下载状态。

## 实施前确认

现有 ComfyUI 0.35.0 已提供 `EmptyFlux2LatentImage`、`Flux2Scheduler` 和 `ReferenceLatent`。从源码和节点 schema 核实：每张参考图经 VAEEncode 后，按顺序同时加入正/负 conditioning；Base 使用 CFG 5，快速版 CFG 1。使用完整 Flux2 VAE，避免在比较模型时同时改变解码器。

人物母版为唯一身份起点。侧面、背面都直接从该母版编辑，避免 A→B→C 多次重绘累积漂移。三视图是外观设计参考，不是标定相机下的几何测量或已验证的三维重建数据。固定 seed 只能帮助复现，不能独立锁定人物身份。

## 本机比较与最终图像配置

已在同一服务器环境和同一 seed 下比较。每种配置一次测试，不是统计显著的大样本评测；前后模型缓存状态不同，耗时不代表冷启动下载或跨硬件性能。

| 任务 | Klein Distilled 4 步 / CFG 1 | Klein Base 20 步 / CFG 5 | 本次观察 |
|---|---:|---:|---|
| 768×1152 人物正面，seed 20260913 | 3.52 秒 | 7.53 秒 | 都有清晰单人全身；快速版更贴近本次自然比例和肤色要求。 |
| 同一快速版母版 → 严格右侧面，seed 20260914 | 3.50 秒 | 15.84 秒 | 都正确转向；Base 额外重绘了较明显的袖章文字细节，未观察到足以抵消成本的一致性提升。 |
| 1344×768 三参考首帧合成，seed 20260918 | 5.75 秒 | 41.07 秒 | 快速版多生成一盏提灯，判为语义不合格；Base 保留一个人物和一盏灯，构图更符合要求。 |

精确耗时以 `runs/klein_compare/*/job.json`、`runs/greenhouse_demo/jobs/firstframe` 的历史记录和服务日志为准。快速版首帧初稿保留在 `ComfyUI/output/references/greenhouse_demo/firstframe_00001_.png`，不能用最终被替换的 assets 路径混淆失败初稿。对比图：[comparison.jpg](../runs/klein_compare/comparison.jpg)。

**历史扩展实验当时选择了混合方案：Klein 4B Distilled 生成正面母版、侧/背图、场景和道具；Klein 4B Base 负责复杂的多图首帧合成及后续单图修正；H3 使用四张参考。该方案已被用户选择的三张独立参考默认替代，不是当前生产推荐。** 当前使用 Distilled 的白底人物、完整场景、白底道具；Base 只保留为按需实验能力。两种图像版本共用文本编码器与 VAE。

可见边界：服装小部件、鞋型和道具比例仍可能被重绘；Base 合成的提灯相对人物略偏大，不能认为文本中的厘米数得到精确执行。首帧中桌面、人物与道具布局可用，但不是测量级资产。没有实测 Qwen Edit，所以不宣称 Klein 在所有人物和视角任务上画质最佳。未来若母版脸部、复杂服装或精确产品几何持续不合格，再以固定评测样本比较 Qwen Edit 2511，而不是悄悄更换模型仍沿用旧结论。

后续修订也证明 Base 并非数量控制或否定约束的保证：第一次“不发光”合成仍点亮灯，改写描述后又出现双灯。因此最终链把复杂构图和单图局部修正分开。这个结论限制了上述单样本比较的推广范围。

单图修正尝试又把灯整体删除，说明它不具备可靠的精确局部编辑保证。本次保留该产物作为干净的布局参考，并让 H3 从独立道具图引入提灯；带单盏亮灯的合成初稿仍单独保存。对于必须逐个部件严格保留的产品图任务，这个版本不应免检自动投产。
