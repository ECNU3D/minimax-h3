# Agent 剪辑与中文字幕工作流

## 默认剪辑与工程交付（2026-10-10 用户指令）

除非用户明确另有要求，本项目以后默认使用 **jianying-editor skill** 剪辑和装配时间线，最终交付**可编辑剪映工程**。此规则优先于下文历史 FFmpeg 单独成片流程；MP4、EDL 和剪辑脚本可以同时交付，但不能代替剪映工程。

1. 开始剪辑前读取 `C:/Users/shang/.codex/skills/jianying-editor/SKILL.md`。已安装的独立环境为 `tools/env-jianying/Scripts/python.exe`，不要把依赖装入 H3 或音频模型环境。
2. 依据 EDL 用独立源片段装配剪映时间线，保留源入出点与可用裁剪余量。已有原声、后配对白、音乐、音效分别保留可编辑轨道；后加字幕、片名和信息卡使用原生文字片段。不能把整条成片放进单一视频轨就视为完成多轨工程交付。
3. 叙事取舍沿用 narrative-video-editor；FFmpeg 可用于素材适配、复杂合成、声音处理、辅助渲染和质量检查。处理结果回到剪映时间线。优先保留原生可编辑裁切和文字；必须烘焙的效果记录清楚，保留源素材与重建资料。
4. 新建唯一名称的草稿，修改已有草稿前先备份，保护用户手工修改。将所需素材副本与工程一起打包，记录来源、哈希及剪辑映射；迁移到其他路径时提供素材重定位或新草稿导入方式。初始工程备份与用户后续在剪映中的保存版本分别说明。
5. 在交付目录的 `剪辑工程/` 中保存草稿、素材和打开说明；用户已指定 `剪映工程/` 等路径时沿用。成片任务同时提供审看或最终 MP4，交付清单必须列出工程位置和剪映中可找到的草稿名称。
6. 检查全部素材路径、时长、帧率、剪点和轨道，并在剪映中验证打开、保存、重新打开。抽查画幅、最长中文字幕、跨镜字幕、片名、关键合成和片尾。首次使用或软件更新造成兼容性不确定时，先做独立小草稿实验。仅写出 JSON 不算验证通过；无法操作剪映 UI 时，仍交付工程并明确哪些检查尚未完成。
7. 硬字幕、已合成屏幕画面及无法等价迁移的混音效果须说明可编辑边界。缺镜和未完成音轨保留明确标记；工程技术通过不等于剧情完整、听音或发布验收通过。

本机已于 2026-10-10 验证剪映 11.5.3.14501 能读取技能生成的明文 `draft_info.json`，并正常保存、重新打开。实证及转换范例见 `原创项目/仿真父母/06_预告片/v6/剪映工程/`。优先复用实测方式，不预设需要降级剪映或调用内部 DLL。

## 剧情完整性修复（2026-10-05）

- 成片剪辑前，将原分镜的必达动作、信息和台词逐项对应到实际采用时间段。镜号在 EDL 中出现，不等于该镜的叙事信息已经送达。
- 不得用裁成脸部特写、插入无关镜头或缩短到动作之前来掩盖生成错误，尤其是刀背试探、同脸换人、看到追兵才逃等因果。用户已明确授权重生成时，应按 H3 固定入口和原逻辑镜号修复、验收，再装配；未授权时记录缺口，不能宣称剧情完整。
- 允许正常选段与压缩，但采用区间必须覆盖该镜承担的完整信息。必要动作和完整台词优先于旧总时长；不为保持旧秒数截掉呼唤、反应、道具和离场。
- 对话题材采用原生声音时，检查视觉提示词与声音段是否存在“禁止人声/留后期”的遗留冲突。音轨存在、ASR 转写、人工试听分开记录；不得自动以后配填补而省略来源说明。
- 每条镜头记录保留、恢复选段或重生成的理由；同一角色的服装、道具和空间关系要跨镜核对。已被用户听审接受的版本保留，避免无理由重抽。

## 声音修订规则（2026-10-05）

此节补充并优先于旧交接包中的笼统“统一音色／全部后配”要求；用户对当前版本的具体选择优先。

- **先审原声，再决定补录。** 列出每句实际来源、可用区间与缺失原因。H3 已有可用对白默认保留，不能为了统一音色整段换成 TTS。字幕或混音问题不重生成画面。用 J/L cut 保留完整词尾，声音切点可以越过画面切点。
- **补录必须明示来源。** 原生 H3、真人、Qwen3-TTS、MiniMax API、程序合成分别记录。用户指定 MiniMax 时，只在指定缺句范围调用 MiniMax；不能用本地 TTS 冒充，也不能无声回退。保存请求文本、模型、voice_id、响应 trace_id、音频哈希与复用关系；不保存密钥到工程日志。
- **音乐先做连续试听，再定切点。** 优先考察已有可授权曲目，记录曲名、作者、来源、许可范围。短片可用一首完整曲目或同一作品的连贯段落；换曲需要叙事理由和可听的衔接。不要按每个镜头生成或拼贴不同音乐。交叉淡化只能处理连接，不能保证不同旋律、调性、配器自然统一。
- **对白优先，音乐用音量自动化避让。** 先平衡对白、环境声、音乐，再做总线限峰与响度检查。淡入淡出、ducking 和恢复速度须在上下文中试听，不逐句硬开硬关。留白由叙事决定，不把每个换镜都当撤音乐的位置。
- **音效必须有对象或明确用途。** 已有合适的原生动作声优先。不能用金属撞击、低频重击、whoosh 机械标记剪点或代替紧张感。未经用户选定，不用正弦波／噪声拼出来的口哨和钢琴冒充音乐素材或真人表演。
- **区分证据。** 波形／非静音检测只能辅助定位，不能证明台词正确、口型吻合或音乐好听；API 字幕也需复核。没有实际听音能力必须写“未实听”，提供成片和独立试听，不能把技术通过写成审美验收通过。

方法参考：[Blackmagic 官方 Fairlight 后期教程](https://www.blackmagicdesign.com/products/davinciresolve/training)、[Adobe 官方对白避让与关键帧调整](https://helpx.adobe.com/premiere/desktop/add-audio-effects/adjust-volume-and-levels/automatically-duck-audio.html)。一首曲目与上述具体取舍是本项目针对反馈的剪辑决定，不宣称为行业统一标准。研究和本次应用见 [声音后期参考与实践](audio-post-practices.md)。

## 固定执行工具

导演台素材包的 `edit-manifest.json.delivery` 指定本次交付位置，默认 `成片/<项目名>/<导出日期时间>/`，子目录为 `视频`、`声音`、`字幕`、`剪辑工程`、`验收`。旧包未指定路径时也沿用这套可读目录，不能只把成片留在 `runs/<任务 hash>/_edit/out`。工程与源素材路径保持可追溯，已有成片使用新版本文件名保留；交付根目录写 `交付清单.md` 并提供实际成片链接。

```powershell
$env:PYTHONUTF8 = '1'
.\scripts\run_ffmpeg_skill.ps1 -Tool probe -ToolArgs @('原创项目/47岁考研/成片/47岁考研-第2集-厨房-90秒.mp4', '--json')
.\scripts\run_ffmpeg_skill.ps1 -Tool cut -ToolArgs @('--help')
.\scripts\run_ffmpeg_skill.ps1 -Tool caption -ToolArgs @('--help')
.\scripts\run_ffmpeg_skill.ps1 -Tool render -ToolArgs @('--help')
```

包装脚本只向子进程 PATH 加入仓库内 `tools/ffmpeg-8.1.2/bin`，不修改系统 PATH 或 H3/音频 Python 包。运行时含 ffprobe 与 libass，来源为 FFmpeg 官方下载页列出的 gyan.dev Windows 构建；版本、发布方 SHA256 校验和二进制哈希在 [ffmpeg-runtime.json](ffmpeg-runtime.json)。此下载是剪辑工具，不涉及模型。
参数放进 `-ToolArgs @(...)`，避免 PowerShell 把 FFmpeg 的 `-o` 误判为自己的 `-OutVariable`。首轮探测后，长编码先 dry-run；不要运行 npx 在线拉最新版，不要擅自装整套 NLE。

## 字幕从粗排到交付

1. 锁定台词原文和 voice master 的 SHA256。测真实声音起止与停顿，再换算到全片全局时间。
2. 先拆语义短句，再定 cue 的时间。跨镜保持同一条全局 cue，烧进各段时裁取交集，不能整段重显。
3. 横片起始样式为 36px 微软雅黑、白字/黑描边、左右 8%、文字实际下边缘 9%、最多 2 行、每行 22 字。对目标平台和画面可调整，不是统一行业硬标准。
4. 文字长则拆句/重排，不缩到 18px。每秒 >9 字、单 cue <0.8s 或 >6s 会提示复查；提示不自动改台词或时长。
5. 根据实际帧避开脸、手和道具文字。固定 cue 用底部或顶部，不能逐帧跳动；画内姓名/日期和对白字幕分别设计。

固定字幕 PNG 排版输入：

```json
{
  "width": 1344, "height": 768, "duration": 10,
  "alignment_status": "unverified",
  "style": {"size": 36, "side": 0.08, "bottom": 0.09},
  "cues": [
    {"start": 0.5, "end": 2.0, "text": "我教计算机"},
    {"start": 2.0, "end": 4.0, "text": "上班跟学生打交道"}
  ]
}
```

```powershell
.\.venv-cu130\Scripts\python.exe scripts/caption_layout.py --cues docs/reviews/47ky-20260916/caption-demo.json --out runs/caption-layout-preview
```

每条可用 `layout: {"position":"top", "protected":[[x1,y1,x2,y2]]}` 覆盖布局。工具先验证所有 cue，再写透明 PNG 与 `layout-report.json`；不调用 GPU。
这是字幕渲染/几何检查，不是 ASR/强制对齐器。示例时间是布局草稿，未经过听音对齐。正式字幕时段需从真实音轨校准；用 ffmpeg-skill caption.py 时读取其 `--text`/`--srt` 格式，不能把这里的 JSON 直接当第三方输入。
第三方 `caption.py --size/--margin` 是相对 288p 脚本高度的 ASS 单位，**不是输出像素**；768p 中 36px 约为 size 13.5（CLI 取 14），69px 边距约 margin 26。固定字号时传 `--fit-size off`，事先拆好 cue，避免它自动缩字/均分长句时间。

## 剪辑与渲染顺序

采用版本清单（真实路径/哈希）→ 声音粗排 → 选素材入出点 → EDL 锁定 → jianying-editor 装配多轨时间线 → 裁切/缩放/调色 → 原生字幕/信息卡 → 最终混音 → 剪映工程保存与打开验收 → 工程及所需审看/成片输出。

- 生成 10.125 秒不等于必须用满 10 秒。按动作与情绪选择入出点；源时长与最终 EDL 时长分开。
- 1344×768 是本机原生比例，不是精确 16:9。要改画幅需明确裁切/补边，不能拉伸。
- 原《47岁考研》build.py 保留为历史可重放工程：旧字幕不会自动变成新样式。新版本先导出 EDL/cue，再调用上述工具；**不要直接在有硬字幕的成片上二次加字**。
- 两集共用声线和可用音乐，复用文件和 transcript；缺失必要音轨必须报错。原 build.py 的“缺少音轨就跳过”不适合正式交付。
- 仅混音时复制视频流并核对流哈希；改字幕/裁切必须重编码相应画面，不能声称仍与原视频流一致。
- 技术体检不过不要全片重做：字体/坐标重排字幕，音量只重混音；不要因此重新生成 H3。

## 验收需要看到和听到

技术：源/最终时长、帧率、音轨、解码、响度、真峰值。视觉：每个剪点、最长字幕、跨镜字幕、屏幕/纸面文字、裁切比例。听音：台词密集段、对白切点、音乐和环境声。
数值检查与视觉/听音分别记录。没有实际听音就写“未听”，没有逐帧浏览就写“抽帧审查”；最终接受属于用户。
