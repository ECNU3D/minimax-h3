## 3. 方案选型

### 3.1 总体取舍

**当前选择：ComfyUI 原生节点 + FL2VA / Ref2VA 量化模型 + NVFP4 文本编码器 + GPU/内存/SSD 动态卸载。**

| 路线 | 本机取舍 |
|---|---|
| ComfyUI | 选用。已有 H3 原生工作流、量化格式、卸载与可视化界面 |
| Diffusers | 适合 Python 集成，但需自行管理流程与卸载，非桌面优先方案 |
| SGLang / vLLM | 适合服务化与多卡，对 16GB Windows 单卡增加复杂度 |
| 云端 API | 不属于本地权重推理，本次不用 |

### 3.2 模型与量化

| 路线 | 说明 |
|---|---|
| FL2VA（FP8） | 一套权重覆盖文生视频与首尾帧图生视频；早期 cu128 兼容路线 |
| Ref2VA（FP8 / INT8 ConvRot） | 全能参考专用主模型；INT8 ConvRot 需 CUDA 13，为官方推荐格式 |
| NVFP4 文本编码器 | `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` |
| 参考图生成 | FLUX.2 Klein 4B（Distilled / Base，Apache 2.0） |

关键约束：
- Ref2VA **不能**用 FL2VA 权重或 FL2V 8 步 LoRA 替代，反之亦然。
- 不能用 FL2V 的 8 步 LoRA 配 Ref2V；Ref2V Turbo 专用 LoRA 为 **4 步**。
- **不要把 FP8 文件重命名成 INT8**；量化格式必须真正下载对应权重。
- Klein 使用独立 `qwen_3_4b.safetensors`（CLIP 类型 `flux2`）和独立 Flux2 VAE，**不能混用 H3 的编码器或 VAE**。

### 3.3 参考图模型选型（Klein 4B 本机比较）

同一服务器、同一 seed、每种配置一次测试：

| 任务 | Klein Distilled 4 步 / CFG 1 | Klein Base 20 步 / CFG 5 | 观察 |
|---|---:|---:|---|
| 768×1152 人物正面（seed 20260913） | 3.52s | 7.53s | 两者都清晰；快速版更贴近本次自然比例与肤色 |
| 同一母版 → 严格右侧面（seed 20260914） | 3.50s | 15.84s | 都正确转向；Base 额外重绘袖章文字，未体现抵消成本的收益 |
| 1344×768 三参考首帧合成（seed 20260918） | 5.75s | 41.07s | 快速版**多生成一盏灯**（语义不合格）；Base 保持一人一灯 |

**结论：混合方案**——Klein 4B Distilled 生成正面母版/侧背/场景/道具，Klein 4B Base 负责复杂多图合成与单图修正。比“一律用更大的 Base”或“一律追 4 步最快”更贴合实际样本。

局限：服装小部件、鞋型、道具比例仍可能被重绘；Base 也不是数量控制或否定约束的保证（曾出现“不发光”仍点亮、改写后变双灯）。因此最终链把**复杂构图与单图局部修正分开**。

## 4. 安装经验

### 4.1 环境搭建要点

1. **冻结能工作的版本，再升级。** 不要每次启动都 `git pull` / `pip upgrade`。
2. **驱动是前置门槛。** CUDA 13 系列要求 R580 或更新驱动家族；576.88 不能承接官方 cu130 最快路线，因此早期先用 cu128 + FP8 兼容路线并实测成功。升级到 591.86 后才启用独立 `.venv-cu130`。
3. **驱动升级后新建环境，而非原地混装。** 新增 `.venv-cu130`，保留 `.venv`，两者共用同一份模型目录。
4. **SageAttention 安装来源固定：** 使用 woct0rdho 维护的 Windows 预编译包，ABI3 支持 Python ≥3.10，stable libtorch ABI 包支持 PyTorch ≥2.10。
   - 本次 wheel：`sageattention-2.2.0+cu130torch2.10.0andhigher.post6-cp310-abi3-win_amd64.whl`
   - SHA256：`1635283f5c01ec3cda58a784d0d7eabbcaffaf9511d1b263db4750e1ed7958bb`（安装时校验）
   - Triton 需匹配：PyTorch 2.11 ↔ `triton-windows 3.6.0.post26`
5. **算子先验证再上整段视频。** 用 56 头 / 2048 token / 每头 128 维做 FP16/BF16 运算，输出有限值，与 PyTorch SDPA 余弦相似度约 **0.99927**（`docs/sage-validation.json`）。这证明算子可执行，**不代表**整段视频质量等价，也不是加速比。
6. **依赖自检：** `scripts/doctor.py`（常规）与 `--hash`（全量读盘校验）；`pip check` 通过。

### 4.2 模型下载经验

- 下载来源为官方仓库的**固定 revision**，逐文件 SHA256 存于 manifest：
  - `docs/models-manifest.json`（FL2VA 5 件套，合计 44,414,604,463 字节）
  - `docs/reference-models-manifest.json`（Ref2VA FP8 + 4 步 LoRA）
  - `docs/int8-reference-manifest.json`（Ref2VA INT8 ConvRot）
  - `docs/image-models-manifest.json`（Klein 图像 4 件，约 16.54GB 十进制）
- **只有通过 SHA256 校验**才会把 `.part` 改成正式 `.safetensors` 文件名。
- 断网/超时：重新运行下载脚本，**保留 `.part` 与 `.aria2`**；分段文件“大小对”不能证明完整。
- 下载 401/403：查日志，确认官方仓库可访问、revision 仍存在；脚本重跑会重新取下载重定向。
- 代理仅本机环境适用（示例 `127.0.0.1:7897`），换电脑需调整；不改变系统代理设置。

### 4.3 启动档位（profile）

```powershell
# cu128 历史基线
.\start.ps1

# cu130 + SageAttention + KJNodes 白名单 + 8GB headroom（当前主力）
.\stop.ps1
.\start.ps1 -Cuda13 -SageAttention -KJNodes -VramHeadroom 8
# 等价双击：start-1080p-sage.cmd
```

- 常用参数：`-Cuda13`（切 cu130）、`-SageAttention`、`-KJNodes`（仅白名单启用，其余自定义节点仍禁用）、`-VramHeadroom <n>`。
- `-ConservativeVRAM` 只用于已记录的**传统卸载失败实验**，**不能**视为已通过的 1080p 方案。
- **服务已在运行时 `start.ps1` 不会自动切换参数**，必须先 `stop.ps1`。
- 切换配置前先查 `http://127.0.0.1:8188/queue`，避免打断其他任务。
- 服务只监听 `127.0.0.1:8188`，默认关闭云端 API 节点与全部自定义节点。不要随意改公网监听。

## 6. 踩坑与解决方案

### 6.1 环境与驱动

| 现象 | 检查与处理 |
|---|---|
| `Torch not compiled with CUDA enabled` | 很可能装了 CPU 版 torch；用对应 `.venv` 按锁定版本重装 CUDA 轮子 |
| `driver too old` / CUDA 初始化失败 | 核对 `nvidia-smi` 与 `docs/gpu-validation.json`；576.88 不适合 CUDA 13，不要直接跑官方 cu130 安装命令 |
| `no kernel image` / `sm_120` 不支持 | 5080 需使用包含 Blackwell 架构支持的 PyTorch |
| 日志提示优化 CUDA operations 需要 cu130 | cu128 路线下 Comfy Kitchen 的 CUDA 加速后端被禁用，属兼容路线的性能限制；是否成功看最终任务状态 |
| `CUDA out of memory` | 停其他 GPU 任务、保持 batch=1、回预览分辨率与 5 秒；必要时重启服务释放残留显存；**不要盲目 `--highvram`** |
| 内存不足 / 页面文件太小 / WinError 1455 | 看任务管理器“已提交”内存；保持系统自动管理分页文件与 C 盘余量；**不要关闭分页文件** |
| `sageattention is not new enough` | 确认用 `.venv-cu130`、正确 wheel 与匹配 Triton，重跑 `scripts/test_sage.py`；不要只凭 pip 无报错判断安装位置 |
| PowerShell 禁止执行脚本 | 使用提供的 `.cmd`（仅对本次进程设执行策略，不改全局） |
| 路径含空格导致命令失败 | 本项目路径含空格，PowerShell 中需引号 + 调用运算符 `&` |

### 6.2 模型与工作流

| 现象 | 检查与处理 |
|---|---|
| 模型文件不在下拉列表 | 确认放对子目录、文件名不含 `.part`；刷新或重启 |
| 缺少 MiniMax H3 节点 | 启动了别处的旧版 ComfyUI 或依赖导入失败；核对服务路径/版本/日志 |
| 加载时 tensor / shape / header 错误 | 先校验 SHA256，再核对模型家族与工作流；**不要改扩展名假装下载完成** |
| 缺 KJ 节点 | 先停止服务，再带 `-KJNodes` 启动；仅导入工作流不会自动启用插件 |
| 黑屏 / 静止 / 严重失真 | 查模型完整性、任务错误、是否漏 Turbo LoRA；回固定种子与示例提示词比较 |
| 没声音 | 查播放器静音；确认工作流连接音频 VAE 与 CreateVideo 的 audio 输入 |
| 画布有节点方框却无文字 | 把右下角缩放调到 80%/100%；约 54% 时文字会被隐藏 |
| 安装了某插件后坏了 | 当前启动脚本禁用所有 custom nodes，先保留该基线排查 |

### 6.3 参考图流程

| 现象 | 检查与处理 |
|---|---|
| 侧面没转过去 / 背面露正脸 | 属语义失败；强化严格 90/180 度描述，从**原始母版**编辑，不覆盖“成功”判断 |
| 人物脸或衣服漂移 | 原母版作主参考；**不要**由侧面继续生成背面；固定种子不能替代图像条件 |
| 首帧人物/道具数量不对 | 明确 Image 1/2/3 各自角色与空间尺寸，避免背景混入 |
| 复杂合成忽略“不发光”或多出道具 | Base 也会出现；提示词否定词**不代表**约束已执行 |
| 视频出现前景光带 | 保留失败样本；查参考是否有发光/矛盾信号；本轮修订同时改了多个条件，**不能**唯一归因 |
| `/free` API 成功但响应体为空 | 客户端须接受空 body；本轮发现并修复该客户端错误 |
| 客户端中断但服务仍在 | 原命令原 run-dir 重跑，用已保存 prompt ID 继续轮询，不重复提交 |

### 6.4 性能与判读

- **不要仅凭低 GPU 利用率判断卡死**：16GB 显存需要卸载与磁盘读取，结合日志、磁盘读取、显存综合判断。
- **同步观察系统内存**：“共享 GPU 内存”统计可能含映射/固定内存，单看它不能断定完全卡死。
- **步数只主要省时间**，不保证降低峰值显存。
- **单次成功 ≠ 长期稳定**；两次耗时比较不能当作固定换算公式。
- **资源采样约 3–5 秒一次**，是整机/整卡观察值，不是精确单进程分配峰值。

## 8. 关键工程决策（可迁移经验）

1. **量化格式与驱动绑定。** CUDA 13 优先 INT8 ConvRot，FP8 是兼容路线；不重命名，不混用。
2. **分块 ≠ 时间分段。** `head_chunks=4 / ffn_chunks=8` 只改变计算分组，降低中间张量峰值，仍保留完整时间序列。
3. **SageAttention 是近似量化计算**，不承诺逐像素等价；须在日志确认 `Using sage attention` 与 `Applying MiniMax H3 Memory Efficient Sage Attention Patch`。
4. **图像与视频串行运行**，阶段切换时请求释放 ComfyUI 模型缓存，避免图像与视频模型同时占显存。
5. **分阶段 CLI 是实际验证路径。** 合并可视化图（combined editor graph）只是附加产物，**不能**当成另跑一次的证据；其存在不代表做过第二次完整测试。
6. **保持 ComfyUI / KJNodes 源码不变**，除非有具体缺陷需要窄修复。
7. **记录纪律：** 每个使用过的提示词、有序参考列表、种子、尺寸、模型 revision、输出哈希与实际结果都要留档；脚本自动写 manifest 与分阶段 job 记录。

## 9. 平台能力边界（避免过度宣称）

- 本地开放的是 **H3-Base**。官方完整系统还含 H3-Context-IR 与 H3-Regenerate-2K 云端模块，**不能**把本地预览描述成完整官方 2K 系统。
- 本次验证的是**这一套具体配置**；增加参考图数量、时长或分辨率都需重新评估显存。
- 未验证：15 秒长视频、Base 20 步大分辨率、多任务并行、连续批量稳定性。
- 参考图、随机种子相同也**不保证**跨环境/跨驱动逐字节一致。
- 音视频检查覆盖格式与信号完整性（有限、非静音），**不含**人耳音质、语义或音画同步主观评分；部分样本解码峰值略高于 1，正式发布前建议检查峰值并限幅。
- 开放权重不等于无条件商用；商业使用前应核对下载仓库当前许可证与官方商业授权要求。
