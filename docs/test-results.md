# MiniMax H3 本机实测记录

测试日期：2026-09-10。所有 H3 推理在本机 RTX 5080 上完成，未调用视频生成云端 API。

2026-09-11 补充：720p 也已跑通，1280×736 生成后裁成 1280×720，124 帧、24fps，服务端 244.73 秒。详见 [720p 实测及复现命令](test-720p.md)。以下保留前两档测试的原始记录。

同日继续补测 10 秒 720p：243 帧、实际 10.125 秒，服务端 679.923 秒，完整解码通过，无 OOM，见同一份 720p 文档。

## 结论

这台 RTX 5080 16GB + 32GB 内存电脑已经跑通 H3 的本地文生视频与原生音频。当前驱动 576.88 下，使用 **ComfyUI 0.35.0 + PyTorch 2.11.0/cu128 + FP8 主模型 + NVFP4 文本编码器 + 动态卸载 + Turbo 8 步** 可完成任务。

建议快速探索使用 640×384；日常清晰预览使用 864×480。它们都是经过本机验证的预览尺寸，并非官方完整 2K 系统。未测试原生 1344×768、15 秒长视频、Ref2VA、多任务并行或驱动升级后的 INT8 路线。

## 复现

在项目目录启动 `start.cmd` 后：

```powershell
& .\.venv\Scripts\python.exe .\scripts\generate.py
& .\.venv\Scripts\python.exe .\scripts\generate.py --width 864 --height 480 --name h3_balanced
```

相同种子不是跨驱动、跨 PyTorch 版本逐字节相同的保证。保留当前版本锁、工作流及权重哈希，才有可比较的复现基线。

## 这次实际遇到的部署问题

1. **驱动与当前官方最快路线不匹配。** 576.88 不能直接承接 CUDA 13 的推荐配置，因此选用 cu128 + FP8，并实测成功。Comfy Kitchen 的 CUDA 优化后端被禁用，日志仍会有 cu130 建议；不要删除警告或宣称全优化能力已开启。
2. **大权重下载吞吐波动。** 起初用 curl 顺序续传，后改用 aria2 分段续传；保留已有文件，完成后做完整 SHA256 验证。
3. **下载过程界面提示两个缺失模型。** 正式权重文件名只在校验后出现，下载完成刷新后错误消失。这不是节点安装失败。
4. **Windows 虚拟环境有启动器与实际解释器两个进程。** 停止脚本验证本项目路径并同时结束对应解释器子进程，防止只关启动器后服务继续占显存。
5. **32GB 系统内存余量偏小。** 即使最小测试也曾只剩约 2.7GiB；保持动态卸载、SSD 与系统管理的分页文件，避免多模型并行。
