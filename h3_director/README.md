# 映场 · 本地 H3 导演台

2026-09-22：参考图默认模型改为本地 **Qwen Image 2.1**，支持文生图、有序参考图生图、画笔/自由套索选区改图；参考图批量任务可保留旧版并全部生成新版本。图片服务使用独立端口 8190，详见 [操作与验证说明](../docs/h3-qwen21-images.md)。

2026-09-20：新增独立「分镜测试」入口，支持原生声音参数、音频参考、环境音与音乐提示词、FLAC/MP4 试听对照和历史参数记录，详见 [使用与验证说明](../docs/h3-shot-lab.md)。直接打开 <http://127.0.0.1:8321/?view=lab>。

面向本机制作的剧本、参考资产、分镜视频与审查工作台。可以导入 Trae 定稿的 Seedance 分镜，也可以让 DeepSeek Agent 从原始剧本拆镜；导演台接手人物三视图、场景与道具参考图、H3 镜头生成、视觉初筛，最后交给 Trae 剪辑。

支持逐步执行和自动制作，保留每次提示词修改、生成版本与审查证据。参考图页“自动制作”仅制作图片，分镜页“自动制作”仅制作视频并先检查参考图审批；制作总览保留“全流程自动制作”。点击后先打开对应阶段的设置窗口，按需选择图片模型（沿用各资产 / Klein Distilled FP8 4 步 / Klein Base FP8 20 步 / Codex Image Gen）、H3 视频画幅与时长、导演 Agent 模型及思考等级、自动初筛开关；确认后才入队。默认的 H3 Ref2VA INT8 768p Turbo 八步档为 24 fps，可生成横屏 1344×768 或竖屏 768×1344。单镜画幅在镜头详情设置，自动制作可统一设置或沿用各镜头画幅。设置对待生成项生效，已有效素材继续复用；保存于项目与该次任务快照，任务记录可查看。

## 1. 启动

双击仓库根目录的 [启动H3导演台.cmd](../启动H3导演台.cmd)，打开 <http://127.0.0.1:8321/>。

首次运行需要已安装 Node.js / npm，并使用仓库已验证的 `.venv-cu130` Python 环境。启动脚本自动安装缺少的 npm 依赖并构建前端；模型与 ComfyUI 依赖的部署见 [本机部署手册](../docs/local-deployment.md)。

在仓库根目录手动启动：

```powershell
# ComfyUI：H3 所需 CUDA13、SageAttention 与 KJNodes 配置
.\start.ps1 -Cuda13 -SageAttention -KJNodes -VramHeadroom 8 -DisablePinnedMemory
# 导演台
.\h3_director\start.ps1
```

导演台端口为 `8321`，ComfyUI 为 `8188`，均只监听本机。导演台在首次需要本地图片或视频生成时，会检查 ComfyUI；未启动则自动调用本仓库 start.ps1，使用 CUDA13 / SageAttention / KJNodes / 8GB headroom / DisablePinnedMemory 配置，并等待最多 90 秒。任务显示启动进度与失败日志位置。已有服务直接复用，不切换其配置；已提交生成或有在途记录时断连，不自动重启。纯解析、审查、Codex 生图和导出不启动 ComfyUI。已有服务时 `start.ps1` 不切换配置，若需切换，先检查 `http://127.0.0.1:8188/queue` 为空，再执行仓库 `stop.ps1` 后重新启动。

只启动 Python API（已有前端构建时）：

```powershell
.\.venv-cu130\Scripts\python.exe h3_director/server.py --port 8321
```

原来的 `h3_director/server.py` 仍是有效入口，具体实现已归入 `backend/`。可用 `--data <目录>` 选择独立项目存储；相对路径以当前终端目录解析。审查 Agent 的独立运行目录仍位于本应用默认 `data/reviewer-runtime/`。

## 2. 制作流程

| 步骤 | 操作与结果 |
|---|---|
| 导入定稿 | 分别上传“参考图生成 MD”和“分镜生成 MD / 原始剧本”，或从仓库选择配对；可只上传一份，原文完整保存 |
| 准备参考 | 生成人物正、侧、背三视图，以及独立场景、道具图；可修改提示词、种子或上传现成图片 |
| 生成分镜 | 为每镜选择并排序参考图，编辑 H3 提示词、时长和种子，预检后生成；保留旧版本 |
| 审查与选择 | DeepSeek 查看真实参考图和视频抽帧，输出通过、修改建议或人工复核；可手动审查已有版本和人工采用 |
| 剪辑交接 | 将当前选中镜头、原稿、叙事说明、哈希与审查结果打包，交给 Trae 的剪辑 Agent |

导入使用 **Codex SDK + DeepSeek v4 flash**，作为异步任务执行，不阻塞页面。两份文档按用途一同送给 DeepSeek，由 Agent 识别文档类型、素材、镜头顺序、台词、时长和跨文档参考关系。不同 Markdown 格式无需改模板代码。已有分镜通过原文行号恢复提示词，原始剧本则生成可编辑的中文拆镜草稿，保留对应原文及制作假设。

**原文优先，默认中文**：参考图文档已有提示词时，按 Agent 标出的行号逐字恢复，不翻译、不追加白底或其他风格模板。主参考、侧面、背面、三视图整合及替代提示词分别保留。缺失部分才由 Agent 用中文补写；资产详情显示原文文件、行号和补写来源，修改后显示“基于参考图原文 · 已修改”。未提供侧背面原文时，使用中文视图指令保持主参考的人物和背景。整合图原文可在“查看原文提示词与其他视图”展开查看、复制使用。

解析分两段 Agent 调用：

1. 解析 Agent 输出素材别名、参考图提示词的原文范围与视图类型、镜头范围及引用关系；缺失参考图提示词时才输出中文 `generationPrompt`。人物的正面与侧背面提示词分开。
2. 独立校对 Agent 对照全文检查漏镜、漏场景、重要台词与因果、资产映射及生成提示词矛盾。未通过时保留报告、不覆盖项目。

Python 只校验源文件哈希、行号、引用、唯一 ID 和显式镜头编号覆盖，不为特定剧本编写语义规则。多集剧本允许每集重新编号：内部镜头 ID 唯一，同时保留原编号和章节。参考图文档里的“分镜 1 首帧”等标题不会计为漏镜。纯剧本拆镜包含导演决策，未知外貌或时长估计会标为制作假设；模型不能保证任意文档绝对无误。固定格式规则解析保留在兼容 API 中。已有项目可在“剧本资料 → 导入 / 补充两份文档”补充另一份文档，同用途使用最新一份；也可点击“DeepSeek 智能解析”重试。已有生成素材时需新建项目，避免覆盖版本。若模型已经完成、仅入库失败，可在任务记录继续原任务，复用源哈希匹配的结果。目前支持 MD / TXT，不支持 DOCX。

**逐步执行**：分别生成资产、生成镜头、审查和导出，随时修改后生成新版本。

**单镜自动制作**：在镜头详情点击“准备参考并生成此镜”，只处理该镜所需资产，自动审查后生成该镜头。

**参考图页自动制作**：仅批量处理参考资产及所选自动初筛，不生成视频或交接包。只有参考图、尚未导入分镜的项目也能使用。设置窗口仅显示图片模型及导演 Agent，选择按阶段分别保存。单张图片未通过审核不会中断整批：按本次设置的最大重试次数自动修订或重抽，仍未通过则保留结果、继续其余图片，全部处理完再标记“待集中人工审核”。图片 B 选择的输入版本 A 即使未通过审核，也可正常用于图片生成；明确选中的版本和哈希不会被悄悄替换。任务记录列出待审资产及版本，参考图页“集中审核 / 待人工审核”筛选显示当前待审项。关闭自动初筛时也先跑完整批，再交人工。生成执行错误、输入文件损坏、在途结果不明确和 STOP 仍会停止，不会被当作普通审核未通过而忽略。

**分镜页自动制作**：仅批量处理分镜视频及所选自动初筛，不补生成参考图或导出交接包。开始前检查所有镜头实际引用的参考资产：当前选中版本必须存在、与当前提示词和参数一致、文件完整，且已通过 Agent 初筛或人工采用。缺失、过期或未通过时，弹窗列出具体资产及受影响镜头，点击“前往参考图”完成准备。未被镜头引用的资产不阻塞。关闭视频自动初筛也不能跳过参考图审批；后端在入队和实际执行前都复核文件哈希，防止绕过页面检查。设置窗口仅显示视频模型、画幅、时长及导演 Agent。

**全流程自动制作**：制作总览入口依次处理参考图 → 镜头 → 审查 → 交接，图片阶段保留已有版本，只补没有图片的资产；视频复用与当前提示词、参数和参考图一致的版本。图片阶段同样先处理完整批，再集中交人工；存在待审图片时不会继续分镜。完成图片审批后可从分镜页开始视频批量制作。视频阶段仍在无法判断、置信度不足或自动重做额度耗尽时停止交人工。

**审核重试**：自动制作设置可填写“每项最大重试次数”（0–10，默认 1，不含首次生成）。0 表示审核不通过后直接交人工；关闭自动初筛时不执行审核重试。阈值冻结在任务快照中，按每个资产/镜头分别计数，暂停、服务重启后沿用原计数。自动批次跳过所有已有图片（含未通过或过期版本）；需要重做时先清空该资产，或手动生成新版本。

审核 Agent（DeepSeek 或 Codex）明确返回 `retryAction` 和中文 `retryReason`：`revise_prompt` 修改主提示词及可选侧背面提示词；`reroll` 完整保留提示词，仅换种子重抽；`none` 不再自动重试。Codex Image Gen 的重抽是新的生成调用，其种子仍不可控。视频修订必须保留有序 Picture 标签，先通过本地校验再进入受保护的 H3 执行器。视频仍受每镜累计最多 2 次提交及原 campaign 的 STOP 约束，用户设置更大的阈值不能增加视频预算。达到阈值的图片进入集中审核列表，图片批次继续执行。

任务记录显示动作、理由、实际重试次数、种子及提示词前后变化；旧版本和原始剧本保留。审核报告的建议与真正执行过的重试记录分开，建议本身不会触发重复提交。

**图片队列**：生成一张图片时可以继续提交其他资产，也可以修改同一资产的提示词再提交一版。按提交顺序逐项执行，不并行占用 GPU；每个任务冻结提交时的提示词、参数和参考图，后续修改不会串入旧任务。相同资产、相同参数的重复提交会被阻止。任务记录可暂停或取消尚未执行的任务。

暂停只阻止该任务的后续步骤，不打断当前 GPU 任务。独立图片任务期间可继续编辑资产；自动制作、解析等整段流程仍锁定会影响该流程的修改。服务重启后的在途任务标为待对账，先核对原任务再继续，不能重新建立重复生成任务。

## 3. 两种参考图生成方式

在“参考图”中打开任意资产，顶部直接选择生成方式和模式：

| 方式 | 文生图 | 参考图生图 | 依赖 |
|---|---|---|---|
| 本地模型 | FLUX.2 Klein 4B Distilled（4 步）或 Base（20 步） | 有序图片进入 ReferenceLatent；保留输入哈希 | 本机 ComfyUI 和已安装模型 |
| Codex Image Gen | 当前登录 Codex 的内置 Image Gen | 附上实际本地图片，调用内置图片编辑 | PATH 中的 `codex`，已登录且账户支持图片生成 |

参考图生图可以上传多张输入、选择已有版本的任一视角，也可以选择尚未生成的上游资产当前主图；支持排序和移除。导入 Agent 用 referenceAssetIds 解析参考图 MD 中的依赖/输入关系，平台转换为 asset:<ID>:0，在批量生成时按依赖顺序实际加载图片，不以文字“同一张脸”代替图像输入。人物侧背面仍直接参考本次正面图。旧项目可点击“识别参考依赖”重新调用当前导演 Agent，仅补缺失连线，不改提示词或素材。循环、自引用和不存在的依赖会被拒绝。上传输入图不会替换生成结果。详情同时展示下一次生成所选参考图、当前版本实际送入模型的参考图缩略图；历史文生图版本明确标注未使用上游图。人物先生成正面，侧面和背面使用本次正面作为身份母版。场景、道具生成单张。每次输出保留版本、提示词、生成方式和输入来源。关键帧独立于空场景，保留原稿中的人物主体和构图。Codex 不保证种子控制，界面会说明。

Codex 通过原生 `app-server` 协议运行 Image Gen，以 `imageGeneration` 返回的真实文件入库，不依靠模型文字猜文件名，也不需要另填 OpenAI API Key。`codex-image.json` 保存线程、turn、文件及失败记录；已有未明确完成的任务不自动重提。

本次本地实测使用 Distilled；Base 选项沿用仓库已有模型管线。

侧栏 **Codex 用量** 使用 `account/rateLimits/read`，显示当前账户剩余百分比与重置时间，每分钟缓存一次。缺失窗口显示未知；服务没有返回独立图片额度时，不把账户百分比换算成图片张数。用量查询不消耗重置额度，不会购买额度。[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)。

每个资产详情可“清空生成结果”：清空当前选中结果及可见版本，让下一次自动制作只补这个缺图资产。文件与版本元数据移入可恢复记录，不删除源文件；有任务运行时不能清空。生成新版本前可“恢复上次清空”。清空上游后，下游旧版本会失去有效参考状态，分镜审批检查仍会阻止使用；系统不会自动重做已有下游图片，需要重做时显式清空。

选中历史版本时，编辑器同步该版本的主提示词、侧背面提示词、种子及已记录参数；“当前图片实际使用的提示词”另保留只读记录。Agent 修改的 V2 不再展示 V1 的提示词。用户后续手动编辑用于下一次生成，不改变旧版本记录。

## 4. H3 参考图与生产约束

2026-10-13：新增「视频生成模式」切换，位于分镜制作列表上方、自动制作设置和独立分镜测试。默认保持 **768p 高质量（1344×768、8 步 Euler）**，可显式选择 **常规快速预览（960×544、4 步 Euler）**。切换只影响后续提交，原有视频、排队快照和预算不变；任务及版本历史会记录实际模式。已有视频仍不会被批量制作覆盖，预览后切回高质量可逐镜点击「生成新版本」。[参数、实测和适用范围](../docs/h3-preview-workflow.md)。

每镜支持 **1–9 张有序图片参考**，并非只能三张。提示词中的 `<Picture 1>`、`<Picture 2>` 等必须与参考列表逐项对应，改变顺序后需同步修改正文。最小样例仍使用白底人物、完整场景、白底道具三张独立参考。

导演台显式使用现有 `--allow-reference-override`，所有视频仍通过 [h3_batch.py](../scripts/h3_batch.py) 提交。人物三视图是资产组，视频默认取该人物选中版本的第一张图；需要把其他视角作为独立 H3 参考时，可作为单独资产上传并加入本镜参考列表。

- “离线预检”检查输入、参考图哈希、Picture 标签与参数；生成时另查 ComfyUI 在线节点和模型选项。
- 同一逻辑镜头最多 **2 次总视频提交**，改提示词、种子或输出目录不重置额度。整个 campaign 累计 3 次执行失败会停止。完整规则见 [生产预算与 STOP 协议](../docs/h3-agent-production.md)。
- 明确的 HTTP 校验拒绝保存回执；提交结果未知、超时或任务失联仍会 STOP，不能盲目重发。
- 每个明确加入队列的图片任务最多自动尝试两版，之后停止；修改后可手动建立新的图片任务。视频仍保留跨任务的两次总提交预算。所有执行完成状态与最终视觉接受分开记录。

可在 Trae 使用 [h3-local-storyboard](../skills/h3-local-storyboard/SKILL.md) 适配本地提示词。官方 Ref2VA 最多 9 图；9 图在本机的性能未做保证。本应用尚未接入视频/音频参考，不等同完整云端 H3 服务。

## 5. 导演 Agent：DeepSeek / Codex 订阅

左侧“导演 Agent”可按项目切换，**默认 DeepSeek**，没有此设置的旧项目也默认 DeepSeek。新建项目时可先选 Codex 订阅，再导入文档。此选择同时用于剧本解析、独立原文校对、参考图审查、视频抽帧审查及自动修订；图片生成方式仍在资产详情单独选择。

Codex 订阅通过同一个 Codex SDK 使用本机当前登录的 ChatGPT 账户，默认模型为 **GPT-5.6 Sol（`gpt-5.6-sol`）**，默认 **Thinking level 为 High**。可在左侧或新建项目窗口选择模型与思考等级；可选项来自账户 `model/list`，仅显示该模型支持的等级。执行前再次核验模型和等级是否可用，不支持时明确报错。运行前检查登录类型，并限制 `forced_login_method=chatgpt`，不注入 OpenAI API Key、不复制登录凭据、不修改用户 Codex 配置。未登录或额度不足时明确失败，不自动切换服务商。账户剩余用量沿用左侧“Codex 用量”。[官方登录说明](https://learn.chatgpt.com/docs/auth)。

任务提交时固定该次执行的 Agent、模型和 Thinking level；有未完成任务时先完成或取消后续任务，再切换。失败的解析任务点击“继续原任务”时，会重新读取工作空间当前的服务商、模型和等级，不会沿用首次提交时的 DeepSeek。此前执行记录单独保留；原稿、逻辑镜头和视频预算不变。解析完成仅更新导入结果，不覆盖后来修改的项目设置。解析与审查记录保存 `provider`、`requestedModel`、`thinking`、线程 ID 和用量，旧报告保留原服务商信息。

DeepSeek 的 Thinking 固定为 **Max（最高）**，解析、行号修正、独立校对、图片和视频审查共用同一设置。SDK 以 `modelReasoningEffort=max` 传入，已通过本机请求验证实际 Responses 请求为 `reasoning.effort=max`；不会用 `xhigh` 代替（DeepSeek 当前会将其映射为 high）。[DeepSeek Responses API](https://api-docs.deepseek.com/api/create-response/)。当前已开始的任务按提交时配置执行，新调用使用 Max。

DeepSeek 配置如下：

密钥保存在**仓库根目录** `.env`，不放在前端或项目 JSON 中：

```dotenv
LLM_PROVIDER=deepseek
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_API_KEY=填写本机密钥
```

[agent/harness.mjs](agent/harness.mjs) 使用 `@openai/codex-sdk` 和 DeepSeek Responses provider；原 `harness.mjs` CLI 路径保留为转发入口。不修改用户 Codex 配置，独立运行目录为 `data/reviewer-runtime/`。

审查会将提示词、参考图和实际视频抽帧发送到所配置的 DeepSeek 服务。本地生成由 ComfyUI 执行；选择 Codex Image Gen 时，提示词和输入参考图发送至当前登录的 Codex 服务。视频约每 0.5 秒采样一帧，包含首尾帧；送审前重新校验源媒体和附件 SHA256。浏览器与交接包不会包含 API Key。

审查输出 `pass / revise / human`、置信度、问题证据、建议及限制。低于 0.75 的信心或存在主要问题不会自动通过。只有合法修订且仍有额度才允许自动重做，接口错误不算通过。界面“审查依据”显示请求模型、参考图和抽帧数量。

`review-input.json` 与 `review.json` 保留附件顺序、时间码、哈希、SDK 线程 ID 和用量。`requestedModel` 记录 `.env` 中的模型名；SDK 不暴露服务商底层实际路由型号，因此 `actualModel` 为 `null`。相关说明见 [DeepSeek 更新](https://api-docs.deepseek.com/updates/) 与 [Codex SDK](https://developers.openai.com/codex/sdk)。

**抽帧审查是视觉初筛**，不能证明完整帧间运动、声音、口型、字幕或发布质量合格。最终人工采用单独记录为 `humanAccepted`。

## 工作空间删除、任务进度与解析修正

点击左侧工作空间名称，在列表右侧点击垃圾桶，确认后移入“已删除工作空间”；展开该列表可恢复。删除当前工作空间会清空当前选择。有排队、执行、暂停或待对账任务时先处理任务再删除。此操作为可恢复删除：保留原文、素材、导出、任务历史和 campaign 预算，不释放磁盘空间；删除后不能访问该项目素材接口或恢复旧任务，需先恢复工作空间。

“任务记录”使用 Codex SDK `runStreamed()` 事件展示解析、修正、独立校对、原文校验、保存及视觉审查阶段；显示本次请求模型/等级、已用时、最近活动、会话 ID、已返回字符数及完成后的 token 用量。模型处理中使用不确定进度条，不编造完成百分比；页面每 4 秒读取任务事件，耗时每秒更新。日志保存于 jobs.json，页面保留最近 200 条事件；完整结构化运行记录见任务目录 process.log。仅公开运行元数据，不公开模型推理或提示词全文；原有无事件的历史任务不能追溯生成实时日志。

Agent 解析结果会先经过本地确定性校验。行号错位、空白或代码围栏错误会反馈给同一服务商的 Agent，最多修正两次，之后停止并保留原稿。修正只返回行号补丁，不允许本地程序猜测或改写提示词；修正后再次校验，再由独立 Agent 校对全文，最终全部通过才入库。重跑时同配置的有效结果可复用，无效结果不会无限重复应用；修正前结果另存备份。

缺少 `referenceAssetIds` 的历史解析缓存不能复用，必须重新解析。参考依赖由 Agent 从上传文档读取，后端仅校验资产存在、无环及输入数量，并转换为可执行引用，不在本地猜测人物对应关系。

解析、行号修正和独立校对的单次调用各有 15 分钟上限，DeepSeek 保持 Thinking Max。解析完成及每次行号修正后立即保存 `data/runs/<任务>/parse-output.json.checkpoint.json`。如果校对超时，继续原任务会复用已经完成的解析，仅重试未完成校对；原文、源文档标识、模型、服务商或思考等级不匹配时不复用。阶段存档不等于导入通过，仍须本地校验和独立校对全部通过才写入项目。超时提示会明确阶段、时间上限及恢复方式。

图片和视频视觉审核也采用单次 15 分钟上限。审核超时表示没有取得结论，不能算作质量不合格或初筛通过，也不触发生图重抽。图片自动批次保留超时项并继续后续图片（后续图可使用它作参考），最后集中待审；素材详情显示“Agent 审查未完成”，可点击“审查版本”重审已有素材。视频审核超时仍停止后续流程，文件损坏、生成执行错误、结果不明确及 STOP 不会被当成审核超时吞掉。

同样的图片批次容错适用于审核接口异常、无结果、JSON/字段结构错误和无效重试决策。当前图片留待人工，后续图片继续，不消耗生成重试次数；有效的 Agent 修订/抽卡建议仍按用户阈值执行。不会从审查正文猜测缺失的 retryAction。原始模型响应保存为任务审核目录的 review-response.json，校验失败仍可排查；后端再次验证返回结构。该容错仅覆盖审核调用及结果读取，不覆盖生成、素材完整性、暂停、STOP 或持久化失败。

分镜批量制作现在同样先完成整批：单镜审核不通过、审核异常、重试达到用户阈值或视频两次提交上限，都保留已有视频，继续后续镜头，最后集中人工审核。单镜操作仍可停下交人工。批量重跑复用已有未过期视频，不重新审核或重抽这些版本；需要修改可单镜操作，但仍受原 campaign 预算限制。已过期且没有重做额度的视频也会保留待审，不申请第三次提交。ComfyUI/生成故障、在途结果不明确、STOP 和手动暂停仍停止；全流程不会自动导出未通过审核的视频。

分镜卡片的“参考图已就绪 · 待生成视频”表示本镜所需参考图已齐全并审批通过，但尚无视频；“待准备或审批参考图”才表示参考输入尚未准备好。“待人工审核”筛选可集中查看已有但未通过的视频。
# 2026-09-20：默认 768p 与逐镜清空

新提交的单镜、自动制作和离线预检默认使用 `ref2v-768p-8step`：1344×768，Ref2V 768p Turbo v1.0，8 步 Euler，shift 12/3。旧任务的已保存 spec 原样恢复；新版本记录实际 profile、campaign 和输入参数。界面中的图像模型4步档不受视频档位切换影响。

分镜详情支持“清空生成结果”和“恢复上次清空”，与参考图操作一致。清空归档版本记录并清除当前选择，不删除源视频；恢复找回原版本及其参数。自动制作只生成当前没有选中结果的镜头，已有视频即使提示词发生变化也保留；要重做时先逐镜清空。参考图审批只检查本次待生成镜头所需资产。

手动清空已有提交记录的镜头，明确开启下一轮制作，保存 campaignHistory 并使用新批次；连续清空其他镜头且尚未提交时沿用同一新批次。旧账本与 STOP 文件原样保留。清空不会提交视频，运行/恢复/自动重试不会重置预算；每镜2次、整批3次失败和不明状态停止仍由 h3_batch 强制执行。

清空视频只检查目标镜头是否有尚未完成的生成或审核任务（包括排队、暂停、待对账）。其他镜头或参考图的任务、无关 ComfyUI 队列不阻塞清空。自动批次中已经完成或原本跳过的已有视频也可清空，但不会被自动加回当前批次；需另外提交生成。清空后既有任务继续使用原快照和原 campaign，产物文件保留，不会修改它们的输入或账本。视频生成队列与 Agent 检测现已分离，详见下节。


### 剪辑素材包与成片目录（2026-09-23）

剪辑导出目录采用 `h3_director/data/exports/<项目名>/<日期时间>/`，ZIP 文件名包含项目名和日期。`edit-manifest.json.delivery` 与 `TRAE-剪辑任务.md` 指定最终交付为仓库 `成片/<项目名>/<日期时间>/`，分为视频、声音、字幕、剪辑工程和验收子目录。剪辑交接页面同时展示素材包位置与计划成片位置；导出只打包输入，不会声称已生成成片。同秒重名使用递增序号，旧素材包与成片保留。

### 视频生成与并行 Agent 检测（2026-09-23）

运行中的导演台使用持久化双队列：GPU 仍只有一个执行槽，视频生成结束后立即继续下一项；视频检测使用 3 个独立 Agent 工作线程，也接收手动“审查版本”任务。参考图自动制作仍按原依赖顺序与审批闸门运行。

- 自动分镜、完整自动制作、单镜生成及准备参考并生成此镜均采用异步视频检测。生成、检测、重试分别在任务记录展示，不必等待检测完成才生成下一镜。
- Agent 决定改词或换种子重试时，新生成任务追加到全局生成队尾，保留原 campaign、镜头名与重试计数。每镜最多两次提交以及 STOP 限制不变。
- 全部视频检测和重试结束后才汇总；有未通过或检测失败的镜头则集中待人工检查，不提前导出交接包。检测服务失败不会被当成重生成指令。
- 暂停阻止派发后续生成与检测，正在执行的步骤完成后保留结果。取消也不打断服务端在途生成；正在运行的检测可以保存结论，但不再追加重试。
- `jobs.json` 中的 `shotTasks` 保存每次尝试的 FIFO 序号、阶段、版本、目录、进程和事件。服务重启先进入待对账，显式恢复原任务后复用原目录，不创建新 campaign 或重置预算。
- 检测只回写对应版本的审核字段，不切换选中版本。若用户修改了镜头/参考素材、生成了新版本或已另排同镜任务，旧检测不再自动覆盖或追加重试；排队重试执行前再次检查输入。

离线验证：`tests/test_async_shots.py` 使用阻塞的模拟审核器测试真实调度入口，覆盖 GPU 与三个审核并行、全局 FIFO 队尾重试、预算、暂停/取消、重启与旧结果保护，不提交 GPU 或调用模型 API。
