# 叙事信息流规划（观众认知时间线）

## Overview

替观众坐在黑暗里的那个人。

整条管线里，storyboard-blueprint 管"这场戏拍什么重点"，shot-rhythm-planner 管"剪辑节奏怎么分、体量多大"，continuity-blocking-planner 管"空间接不接得顺"——但没有人管"一个零背景的观众，在第 X 秒到底知道了什么、多久能得到一件新东西"。本技能补上这一层：信息投放（通道）+ 叙事节奏（频率）。

核心原则：**故事讲没讲清楚，不取决于信息写没写在剧本里，而取决于信息有没有在正确的时间、通过观众实际接收得到的通道、送进观众脑子里。** 剧本里存在 ≠ 观众知道。旁白说了 ≠ 观众记住了。导演脑中清楚 ≠ 画面上可见。

生成前先阅读：

- `references/cognitive-timeline-template.md`：固定输出结构
- `references/channel-rules.md`：四通道分工规则与旁白写作规范
- `references/beat-rhythm-rules.md`：拍点定义、叙事节奏硬性指标与体量系数表（全管线唯一标准源）
- `references/explainer-formula.md`：解说漫剧结构配方（悬念前置六步法，处理解说体裁时必读）
- `references/comprehension-checklist.md`：五项硬性检查与盲审/静音自测协议

## Scope Decision

可处理的对象包括：

1. 一份剧本 / 分镜对白脚本（最佳介入时机：平台提示词生成之前）
2. 一份导演分镜蓝图
3. 一份已完成的平台分镜脚本（回溯诊断模式）
4. 一集连载中的单集（需要额外做跨集信息检查）

体裁差异：

- **剧情漫剧**：目标是"静音也能跟上主线"。画面动作是第一通道，台词第二，旁白限额，字幕只做时间地点锚。
- **解说漫剧**：目标是"旁白与画面互补而非配图"。旁白是第一通道，但每条旁白必须绑定画面证据（画面在演旁白说的事，而不是旁白在解释无关的漂亮画面），且关掉旁白时画面至少不与故事线冲突。**结构必须走 `references/explainer-formula.md` 的悬念前置六步法**（冷开场钩子/命名锚定/计数框架/枢纽可见+判决上卡/先白话后引文/K卡清单）——按时间顺序平铺+段尾金句是解说漫最常见也最致命的写法。

## Workflow Overview

按下面顺序执行：

1. 提取信息资产清单（观众必须知道的每一条事实）
2. 做观众先验知识审查（脚本假设观众已知什么）
3. 建观众认知时间线（逐镜申报信息增量、通道与拍点类型）
4. 叙事节奏核算（拍点间隔 / 空窗地图 / 放大配比 / 钩子与转折位置 / 体量）
5. 跑五项硬性检查（枢纽可见 / 内心转译 / 通道冲突 / 依赖顺序 / 人物锚定）
6. 自测：盲审复述 + 静音测试
7. 输出修改指令清单，路由到对应技能

## Step 1: 提取信息资产清单

通读全稿，列出**零背景观众看懂这个故事所必须知道的全部事实**，每条编号（I1、I2……），分五类：

- **身份**：这个人是谁、什么职务、和谁什么关系
- **前史**：开场之前发生过什么（最容易被压进一句台词然后丢失）
- **动机**：他想要什么、为什么
- **因果规则**：这个世界里"A 导致 B"的规则（含世界观设定）
- **当下事件**：正在发生什么、赌注是什么

每条信息标注：

- 重要度：`枢纽`（看不懂它=看不懂全片）/ `支撑` / `氛围`
- 首次送达位置（镜号）
- 送达通道（见 Step 3）
- 是否需要二次触达（枢纽信息默认需要——第一次铺垫、第二次确认，两次用不同通道、间隔至少一个段落）

数量本身就是诊断：**5-10 分钟的片子，枢纽信息超过 7 条就已经过载**，先做减法再做设计。

## Step 2: 观众先验知识审查

列出脚本隐含假设观众已知的一切：原著情节、行业常识、上一集内容、类型片惯例。

每条假设三选一：

1. **删除依赖**：改写剧情，让不知道的人也能看懂
2. **补建前提**：在依赖点之前用最便宜的通道补交代（一句台词/一个画面/一条字幕）
3. **明示接受**：确认目标观众确实都有这条先验（写明理由，例如系列固定粉丝），并标注风险

改编名著/历史题材时本项为最高优先级：创作者全程带着原著记忆工作，是"讲不清楚"最大的单一来源。

## Step 3: 建观众认知时间线（核心产出）

逐镜（或逐节拍）填表，字段：

| 镜号 | 观众此刻已知 | 本镜信息增量 | 拍点类型 | 通道 | 依赖的前置信息 | 风险 |

规则：

- **每镜必须标注拍点类型（四选一）**：`信息拍` / `情绪拍` / `放大`（须标挂靠对象）/ `呼吸`。定义与判定铁律见 `references/beat-rhythm-rules.md`——同一事实的第 2、3 次证明是放大，不是新拍点；给放大镜头编"伪增量"是本表最常见的自欺。
- **信息增量必须写成观众语言**："观众现在知道女主是死者的女儿"，而不是"揭示母女关系"。写不成观众语言的增量（如"暗示宿命感"）自动降级为放大或呼吸。
- **依赖检查**：本镜增量所依赖的每条前置信息，必须已在更早的镜头送达。依赖悬空 = 信息断点，标红。
- **通道申报**：每条增量指定唯一主通道——`画面动作` / `台词` / `旁白` / `字幕`。通道分工与配额规则见 `references/channel-rules.md`。

## Step 4: 叙事节奏核算

用 Step 3 的拍点标注，按 `references/beat-rhythm-rules.md` 的"快速核算流程"算出并写进文档：

1. **独立拍点数 N** 与平均间隔（全片时长 ÷ N）
2. **空窗地图**：每段连续无新拍点的起止秒数与时长，超过 60 秒（解说漫剧 30 秒）逐段标红
3. **前 60 秒钩子**：主角是谁 / 当下情境 / 值得看下去的问题——三要素逐项打勾
4. **主转折位置**：全片最大认知反转落在百分之几处
5. **放大+呼吸配比**：时长占比、最长连续段、逐个核对放大挂靠是否在 60 秒内
6. **体量核对**：N × 类型系数 → 合理时长区间，与目标时长对照；超上限默认裁时长，禁止用放大/呼吸填差额

**这一步的结论直接决定修改指令的方向**：空窗和配比超标的修法是删/合并/前移，不是给镜头换运镜。若选择艺术片模式，必须在此声明并通过媒介错配审查（情绪押在微表情/声线上=AI 交付不了，退回选题层）。

## Step 5: 五项硬性检查

1. **枢纽事件可见性**：每个改变故事走向的事件（杀人、背叛、发现、决定）必须以可见的外部动作出现在画面里。用白光、黑幕、隐喻代替枢纽事件 = 直接不通过。艺术化处理可以叠加在可见动作之上，不能替代它。
2. **内心活动转译**："他明白了""他想起了母亲""他下定决心""双方摸清了底牌"这类内心支点，必须先转译成可拍摄的外部行为（动作、道具交互、可听台词），才允许进入分镜。转译不出来的，改剧情或删。
3. **通道冲突**：同一信息禁止同镜双通道重复（旁白转述画面里刚说过的台词=最常见浪费）；画面拍得出的不许旁白说。
4. **依赖顺序**：Step 3 标红的悬空依赖必须清零。
5. **人物锚定**：观众记不住名字，只记得住"视觉标签+功能称呼"。每个关键角色首次出场必须绑定身份标签（制服/道具/一句点明身份的台词/字幕）；**只闻其声不见其人的角色是最高风险**——若剧情需要隐藏面孔，必须给他一个可见的代理物（头衔字幕、聊天界面备注、他人转述其身份），并让名字在关键点前至少出现两次。

## Step 6: 自测——盲审复述 + 静音测试

交付前必须自跑两个测试并把结果写进文档：

- **盲审复述**：只看每镜的画面描述（遮掉台词/旁白/字幕栏），从头走到尾，写出"一个没读过原著、不认识创作者的人"能复述出的故事。复述断在哪，哪里就是画面失语点。
- **静音测试**（剧情漫剧）/ **黑屏测试**（解说漫剧）：剧情片关掉声音轨，主线因果是否仍可跟随；解说片遮掉画面只听旁白，再对照画面是否在"演"旁白说的事——若旁白独立成立而画面可有可无，判定为配图片，不通过。

测试执行建议：由一个不带上下文的独立审读者（或新开对话的 agent，只给画面栏）来做，创作者自测天然带上帝视角，结果仅供参考。

## Step 7: 输出修改指令与路由

诊断出的每个问题给出可执行修改，按层路由：

- 信息总量过载 / 枢纽信息超过 7 条：回上游剧本层做减法（story-creator / 手改剧本）
- 拍点密度不足 / 空窗与配比超标 / 体量超上限：给出裁时长方案（删/合并/前移哪些镜位），交 `shot-rhythm-planner` 做体量裁定与重分配；若要保时长，回剧本层加新剧情（新拍点），禁止加镜头凑长度
- 剧情重点或段落结构要动：回 `storyboard-blueprint`
- 只需增删镜头或改单镜内容：直接给出逐镜修改指令，交平台分镜技能执行
- 台词/旁白要重写：给出改写后的完整文本（不是"建议精简"这种空话）
- 修改完成后：交 `storyboard-reviewer`（其"信息传达"维度会用同一套标准复查）

## Output Rules

严格按 `references/cognitive-timeline-template.md` 的结构输出。

默认文件名：

- `{标题}-观众认知时间线.md`

文档必须包含：

- 信息资产清单（编号、重要度、送达位置、通道、二次触达）
- 先验知识审查表
- 逐镜认知时间线表（含拍点类型）
- 叙事节奏读数（拍点统计、空窗地图、钩子与转折位置、放大配比、体量裁定）
- 五项硬性检查结果
- 盲审复述原文与断点标注
- 修改指令清单（按优先级排序，含改写后文本）

## Review Gate

输出后先让用户审阅，重点确认：

- 信息资产清单有没有漏掉/多算（用户比技能更清楚哪些是枢纽）
- 先验假设三选一的选择是否符合目标观众
- 修改指令的改动范围是否可接受
- 枢纽事件可见化的方案是否符合审美底线（可见 ≠ 血腥直白）

明确提醒：

- 这是一份信息流规划文档，不是分镜修订稿
- 通过后按路由交给对应技能执行修改

## Quality Bar

以下情况视为失败：

- 时间线表里出现"渲染氛围""强化情绪"这类无法翻译成观众语言的信息增量
- 给放大镜头编造伪增量（"观众知道他也会关心咳嗽"）混过拍点统计
- 空窗或配比超标，修改指令却只建议换运镜/调时长——把叙事节奏问题当剪辑节奏修
- 体量超上限时用增加放大/呼吸镜头把目标时长填满
- 枢纽事件用隐喻/黑幕蒙混过检查
- 盲审复述由创作者本人或已读过全稿的同一会话完成，却标注为独立盲审
- 修改指令只有方向没有文本（"建议补交代方浩身份"而不给出补在哪一镜、用什么台词/画面）
- 对解说体裁只检查旁白通顺，不检查画面是否在"演"旁白
- 信息过载时不做减法，只往旁白里塞更多解释
