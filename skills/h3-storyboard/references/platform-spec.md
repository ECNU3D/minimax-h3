## 1. 输出规格

| 维度 | 值 | 对分镜的影响 |
|------|-----|-------------|
| 单条时长 | **4-15 秒** | 单镜模式取 4-8 秒；序列模式取 10-15 秒 |
| 帧率 | 24 FPS | 与电影一致，慢动作段落要显式写「慢动作」 |
| 分辨率 | 768p 模式（后续开放，可升级至 1440p）／1440p 模式 | 定稿交付走 1440p |
| 声音 | **所有结果全部带声音输出，原生双声道** | ⚠️ 见下方警告 |
| 提示词上限 | **7000 字符** | 序列模式容易逼近，写完要数字符 |

**分辨率细则**：宽高比在 16:9~9:16 之间时，输出为短边 768 / 1440 像素；超出该范围时按总面积算——768p 约 1M 像素（21:9 → 1536×672），1440p 约 3.7M 像素（21:9 → 2976×1248）。

> ⚠️ **「全部带声音输出」是 H3 与多数模型最大的差异**：你不写声音，它也会自己配环境声甚至配乐。多条素材各自随机配乐，剪到一起必然打架。
> 所以每条提示词都必须显式管声音，二选一：
> - **白名单钳声**（推荐，手册案例的标准做法）：`声音只使用厨房室内环境声、抹布摩擦声、马克杯轻微碰撞声、水龙头水滴声、拍摄者的脚步声与轻微呼吸声`
> - **完整点单**：把 BGM 的风格配比、乐器、分段编曲进程全写出来（写法见 `prompt-patterns.md` 第 5 节）
>
> 若全片音乐走后期统一设计，白名单里就**不要放音乐**，并补一句 `不要背景音乐`。

## 2. 三大入口与素材限额

### 首/尾帧入口

- 图片：**0、1、2 张**（0 张 = 退化为文生视频；1 张 = 首帧；2 张 = 首帧 + 尾帧）
- 图片宽高范围 [256, 5760]，宽高比须在 5:2 ~ 2:5 内
- 适用：需要精确控制起止画面、做跨镜首尾帧链承接

### 全能参考入口

- **图片 ≤ 9 张**，宽高范围 [256, 5760]
- **视频 ≤ 3 段**，单段时长 [2, 15] 秒，**总时长 ≤ 15 秒**，宽高范围 [256, 5760]，宽高比 5:2 ~ 2:5
- **音频 ≤ 3 段**，单段 [2, 15] 秒，总时长 ≤ 15 秒，**必须配图片或视频输入，不能单独输入音频**
- **混合输入总上限 12 个文件**（图 + 视频 + 音频 相加）
- 无任何输入时退化为文生视频
- 适用：角色/场景/道具锚定、动作迁移、运镜迁移、剪辑节奏迁移、音色克隆、视频编辑

### 文生视频

- 无素材输入，纯文字
- 唯一能完全自由指定宽高比的模式

**写分镜时必须为每一镜标注走哪个入口**，因为下游上传操作、宽高比设置、素材准备清单都不同。

## 3. 宽高比控制权（最容易踩的坑）

| 入口 | 宽高比由谁决定 |
|------|--------------|
| **首/尾帧模式** | **遵循用户输入图片的原始长宽比**——你在提示词里写「9:16 竖屏」是无效的 |
| 文生视频模式 | 用户指定：21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16 |
| 全能参考模式 | 用户指定上述比例，或选「自动」由 H3 自行判断 |

**推论（写脚本时直接照做）：**

1. 走首尾帧入口的镜，**参考图必须先按目标画幅裁好再上传**。上游生图环节就要按 9:16 或 16:9 出图，不能出 1:1 再指望提示词纠正。
2. 同一支片子里混用入口时，**逐镜核对画幅**——首尾帧镜跟图走、文生镜跟设置走，很容易出现一条 16:9 一条 4:3 剪不到一起。
3. 全能参考模式**不要用「自动」**：多条素材各自自动判断，画幅会飘。显式指定。

## 4. 素材格式与体积

| 类型 | 格式 | 单文件上限 |
|------|------|-----------|
| 视频 | H.264/AVC、H.265/HEVC（视频内音频 AAC、MP3） | 50 MB |
| 图片 | JPG、JPEG、PNG、WEBP、HEIC、HEIF | 30 MB |
| 音频 | WAV、MP3 | 15 MB |

- 加总不限制，限制都在单个素材上。
- API 请求体 64 MB，**推荐用 URL 传素材**而不是内联上传。

## 5. 素材引用语法

手册案例中两种写法都出现：

- 多数写作 `图1`、`图2`、`视频1`、`音频1`（例：`图1是整体质感、氛围参考，图2是人物外表特征参考`）
- 少数写作 `@图片1`、`@图片2`（例：咖啡表面转场沙漠案例）

**本技能统一用 `@图1` / `@视频1` / `@音频1` 的带 @ 写法**——@ 让引用在长提示词里不会和普通名词混淆，也与同族技能（seedance / vidu / hailuo / wanxiang）的审阅习惯一致。编号必须与实际上传顺序严格一致。

**素材职能声明**是 H3 提示词的标准开头，手册几乎每条多素材案例都这么写：

```
整体氛围、场景和胶片质感参考@图1；人物资产参考@图2；包袋资产参考@图3；品牌 ending logo 参考@图4。
```

```
@图1 是整体质感、氛围参考，@图2 是人物外表特征参考。
```

```
使用@图2作为固定人物参考，保持黑色半扎长发、银色镂空发冠、黛蓝发带、浅色层叠汉服……一致。使用@图1作为镜头分镜、节奏参考。
```

**没有职能声明，H3 会自己猜每张图是干什么的**——传 4 张图却不说谁是人物谁是环境谁是 logo，是多素材翻车的头号原因。

## 6. 语言与 TTS

- 支持多语言提示词输入与输出。
- **TTS 精准覆盖 11 种语言**：中文、英语、日语、韩语、法语、德语、西班牙语等。
- 更多语言可衍生探索：阿拉伯语、泰语、印尼语、印地语等 40 多种。
- 适用：海外品牌传播、多语种广告、跨语言短片、本地化产品介绍。

**做多语种版本时**：同一支片子的多语言版，优先用同一批参考素材 + 同一套画面描述，只换台词语言，保证画面完全一致；音色一致靠给每个语种挂同一条 `@音频1` 音色参考。
