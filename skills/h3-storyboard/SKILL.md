# MiniMax H3 分镜提示词生成器

## 本仓库本地部署：先选能力边界（2026-09-16）

当任务是在本仓库调用 ComfyUI/本地权重，先读仓库根目录的 `docs/h3-agent-production.md`，执行交给 `skills/h3-production-runner/SKILL.md`。
下面的云平台视频编辑、视频/音频参考、音色迁移和“中文画字强项”等介绍**不能自动套用本地节点**。当前 `generate.graph()` 的 Ref2VA 入口接收静态参考图，不接受视频或音频文件作为参考。

- 当前默认三张独立图，按人物白底/完整场景/道具白底排序，并转换为实际 `<Picture 1>` 等标签；不默认第四张构图图、合成首帧、抠图或平台 `@视频` 输入。
- 当前本机验证规格为 1344×768、24fps、10秒请求实际243帧/10.125秒；需准确中文信息用后期字幕/UI，不以模型画字成功作保证。
- 人声采用后期本地 TTS 的项目，沿用声画分轨；不写台词让 H3 再随机配音。原 H3 音轨仍保留为源文件。
- 缺参考资产时用本地参考流水线 `--until references`，不要调用下文历史的 `gpt-image-bridge` / macOS 私有路径。
- 手部/纸张/镜面是本项目风险，不是永久禁区；生成预算由固定脚本执行，不能因技能说“不合格重抽”无限续跑。

仅当用户明确要求云平台提示词时，才按下文平台规格分支组织输出。

## 概述

把用户输入转化为 MiniMax H3 的可粘贴提示词，并保存为 Markdown 文件。H3 与同族平台（Seedance / Vidu / 海螺 / 万相）有四处结构性差异，**这四处决定了本技能的写法**：

1. **输出全部带声音（原生双声道）**——不管声音就随机配乐，多条剪一起必打架。
2. **单条可承载多镜序列**（15 秒内含多次硬切与转场），也可以只做一个连续镜头。
3. **已有视频可作输入做精准编辑**（换角色/背景/光影/台词/音色，一条指令改多处）。
4. **画面内文字是强项**，本技能允许模型画字（含中文），配验收规范。

## 第一步：判定任务模式

| 用户给的是 | 走 |
|-----------|-----|
| 文字、故事、剧本、创意、产品需求 | **生成模式** → 继续第二步 |
| 已有视频 + 「改 XX」「换 XX」「加 XX」「去掉 XX」 | **编辑模式** → 读 [references/edit-mode.md](references/edit-mode.md)，然后直接跳到第五步输出 |
| 已有视频 + 「参考它的动作/运镜/节奏/音色做新的」 | **迁移模式** → 同样读 [references/edit-mode.md](references/edit-mode.md) 第 5 节 |

模式判定错了后面全白做——用户说「这条别的都好就是背景不对」是编辑模式，说「整体感觉不对重来」才是生成模式。

## 第二步：选入口与画幅

每一镜都要标注走哪个入口，因为上传操作、画幅设置、素材清单都不同。完整规格见 [references/platform-spec.md](references/platform-spec.md)。

| 入口 | 可传素材 | 画幅由谁决定 |
|------|---------|-------------|
| **首/尾帧** | 图片 0/1/2 张 | **跟随输入图片原始长宽比**——提示词里写画幅无效 |
| **全能参考** | 图 ≤9 · 视频 ≤3（单段 2-15 秒，总 ≤15 秒）· 音频 ≤3（须配图或视频）· 合计 ≤12 个文件 | 用户指定 21:9/16:9/4:3/1:1/3:4/9:16 |
| **文生视频** | 无 | 用户指定，最自由 |

> ⚠️ **硬规则：走首尾帧入口的镜，参考图必须先按目标画幅裁好再上传。**
> 上游生图环节就要按 9:16 或 16:9 出图，出了 1:1 再想靠提示词纠正是不可能的。
> 全片混用入口时逐镜核对画幅，别出现一条 16:9 一条 4:3 剪不到一起。全能参考模式**不要选「自动」**，多条各自判断画幅会飘。

## 第三步：定粒度（单镜 / 序列）

| 判定信号 | 模式 | 时长 |
|---------|------|------|
| 需要逐镜精修、逐镜验收、跨镜首尾帧锚定；叙事片、短剧、漫剧 | **单镜模式**：一条 = 一个连续镜头 | 4-8 秒 |
| 整段一次成型；片头包装、TVC、预告片、UI/UX 演示、产品卖点片、mood film | **序列模式**：一条 = 一个多镜段落，含硬切转场 | 10-15 秒 |

**序列模式的代价必须先告诉用户**：段内单个镜头不能单独重抽，任何一处翻车整段重来；且与逐镜验收流程冲突，验收清单要写成段内逐镜检查项。**拿不准就走单镜模式。**

**分镜数量参考（单镜模式）：**

| 内容类型 | 建议分镜数 |
|----------|-----------|
| 单一场景 / 简单动作 | 1 个 |
| 2-3 个场景转换 | 2-3 个 |
| 完整短片 | 4-6 个 |
| 复杂叙事 | 7 个或更多 |

## 第四步：构建每条提示词

**H3 六段式骨架**（顺序不要乱，缺哪段在哪段翻车；写法、模板与词库见 [references/prompt-patterns.md](references/prompt-patterns.md)）：

| 段 | 内容 |
|----|------|
| ① 交付规格 | 时长 + 画幅 + 体裁 |
| ② 素材职能声明 | 每个素材干什么用——`@图1 是整体质感、氛围参考，@图2 是人物外表特征参考` |
| ③ 一致性锁定 | 必须锁死的外观**逐部件点名**，不是只写「与参考图一致」 |
| ④ 内容主体 | 单镜描述，或 `[0秒-2秒]…` 时间轴式 / `Shot 1 — … Audio: … → Hard cut.` 序列式 |
| ⑤ 声音设计 | 白名单钳声 或 完整 BGM 点单 |
| ⑥ 负面清单 | 按体裁取用，见 prompt-patterns.md 第 7 节 |

提示词上限 **7000 字符**，序列模式容易逼近，写完数一下。

### 硬规则一：素材引用必须写进可复制的提示词正文内

`@图X` / `@视频X` / `@音频X` 要出现在**代码块里**，不能只写在代码块外的说明行。用户复制的是代码块内容，H3 全能参考也是靠正文里的引用才知道该镜用哪个素材、锁什么。只写在代码块外（如「- 参考图：@图1」这类人读的说明行），复制粘贴时会整体丢失，素材等于白传。

每条含参考素材的正文都要有对应引用 + 一句该素材锁什么（`@图1 锁定产品外观商标不可变形`）。代码块外的说明行可保留供人审，但**不能替代**正文内引用。编号必须与实际上传顺序严格一致。

**编号必须按本镜实际上传张数从 1 连续编，禁止用全局固定映射。** 全能参考是**按拖入的先后顺序**编号成 图1/图2/图3 的，不是按文件名。最容易犯的错：定一套"图1=首帧、图2=角色、图3=场景"的全局约定，然后在**没有角色的镜**里照样写 `@图3 锁定场景`——那镜只传了 2 张，`图3` 根本不存在，**这个锚定会被静默忽略**（不报错，只是跨镜一致性悄悄失效）。

- ❌ 本镜传 2 个素材，正文写 `@图1 … @图3 …`
- ✅ 本镜传 2 个素材，正文写 `@图1 … @图2 …`；传 3 个才可以写到 `@图3`

每镜还要在代码块**外面**紧挨着写一行上传顺序对照，文件名只写在块外（复制时不带进去），块内保持纯 `@图X`：

```
📎 上传顺序（拖入「全能参考」，顺序不能错）：
   图1 → 参考图/首帧/S02.png
   图2 → 参考图/场景2-烤串摊.png
```

写完自检：逐镜比对「📎 里列了几个素材」与「正文里最大的 @图/@视频/@音频 编号」，必须相等。

### 硬规则二：正文必须自包含，严禁跨镜引用

H3 生成每一条时是**独立的、没有任何上下文**，它没见过「镜10」「上一镜」「开篇」。这类词写进可粘贴正文对模型**完全无效**：

- ❌ 跨镜引用：「与镜X一致」「承接镜X」「与开篇同机位」「复用同素材」「供镜X使用」
- ❌ 依赖记忆的词：「维持XX」「沿用XX」「与之前的XX一致」「XX首次进场」「母题连续」
- ❌ 画面外对照：「与全片红烟形成对比」（本帧没有红烟，模型无从对比）

**一旦写出这类词，就是锚定没到位的信号。** 跨镜一致性只能靠三种真正有效的锚定，可并用：

1. **详细的自包含描述**——把要一致的东西在本镜正文里从头描述清楚（不写「与镜06 那把蒲扇一致」，写「枯黄蒲扇、扇缘深褐色火烧焦痕与焦黑缺口、竹骨放射状花纹」）。
2. **参考图锚定**——多个镜头挂同一张 `@图X`。
3. **参考视频锚定（H3 独有）**——把已生成的成片段落作为 `@视频X` 传入，锁人物、锁画风、锁剪辑节奏。`≤3 段视频、总 ≤15 秒` 的额度优先留给这种跨镜锚定。

跨镜连续性**意图**（首尾帧承接、转场、同机位）只能写在代码块外的操作说明行给人看，注明「生成操作：把镜X尾帧作本镜首帧上传」——**绝不能进入正文**。
写完自检：把每个代码块单独拎出来读，确认脱离全文也能独立生成、不含任何「镜编号/维持/一致/承接/之前」。

### 硬规则三：声画分轨 + H3 钳声

完整规则、语速表与自检清单见 `narrative-info-planner/references/audio-lane-rules.md`。

> **H3 前提（比其他平台更严）**：H3 **所有结果全部带声音输出，原生双声道**。①正文里出现带引号的话，H3 一定会给它配语音——每个引号都是一次下单；②**就算你一个字不写，H3 也会自己配环境声甚至配乐**。
>
> 所以每条提示词的第 ⑤ 段都必须显式管声音，二选一：
> - **白名单钳声**（默认）：`声音只使用{穷举允许出现的声音}`。若全片音乐走后期统一设计，白名单里不要放音乐，并补 `不要背景音乐`。
> - **完整 BGM 点单**：风格配比 + 乐器清单 + 分段编曲进程 + 情绪定调 + `不模仿任何现有旋律`。
>
> **漏写钳声 = 每条素材各自随机配乐，剪到一起必然打架。**

写任何台词／旁白／广播／画外音／内心独白之前，二选一盖章：

- **🅐 模型生成（写进正文）**：画面内人物开口说话、有可见口型、且不承担品牌必听信息。必须绑定到具体时间段（`2-6秒：她开口："……"`），必须过时长预算，正文补写 `口型与中文台词一致`。
- **🅑 后期录制（一个字都不进正文）**：命中任意一条即强制走 🅑 ——①品牌名／产品名／Slogan／必听信息（模型会吞字改词读错品名）；②画外音、广播、旁白、内心独白；③需要精确卡点／响度／跨镜连续；④时长超过所在时间段容量；⑤脚本别处已写「必须后录」。

> **H3 对第 ② 条的唯一放宽**：H3 支持音色参考（`音色参考@音频1`，音频须配图或视频一起传）。当画外音／旁白**同时满足**「已挂音色参考音频」+「不承担品牌必听信息」+「不需要精确卡点」时，可以降级走 🅐。
> 但音色参考只解决**音色一致**，不解决吞字、读错品名、卡点——①③⑤条**一律不放宽**。首次这么用时按一条素材试拍确认，别整片压上去。

🅑 的正文**只写声源的可见物理动作**，并在禁令段写死 `无人声、无对白、无旁白、无画外配音，人物不开口说话`：
- ❌ `老扬声器通电，画外童声广播"请不要在戏院食用——小小酥"，他的扫帚停住`
- ✅ `墙上老式金属扬声器亮起一点电流指示光并轻微震动，他的扫帚立刻停住，肩膀微收`

台词原文只写在代码块**外**的「声音／后期」行、声音时间轴和装配规范里。**同一句话同时出现在代码块内外 = 双轨冲突**，删掉代码块内那份。

**台词时长预算（🅐🅑 都要算）**：`可容纳字数 ≈ (窗口秒数 − 0.4) × 语速`；语速取 快对白 5 ／正常对白 4.5 ／广告旁白 4 ／失真广播·强调句 3–3.5 字每秒；破折号省略号每处再扣 0.3 秒，逗号扣 0.15 秒。
装不下的三条出路（**禁止靠「念快点」硬塞**）：砍字 → 跨镜（仅 🅑，须在声音时间轴写明跨镜区间）→ 换成后期字幕／可见动作。
**预算算的是「成片窗口」，不是「生成时长」**：`生成 15s / 成片 6s` 这类写法里，台词写在 `0-15秒` 看着宽裕，但观众只看得到剪进去的 6 秒——用成片时长算，并写明这句落在素材的哪一段。

**音效同理**：若全片声音走后期设计，正文里不要写 `第二声脆响发生`，改写产生该声音的可见动作 `牙齿清楚咬穿米果，碎屑轻微迸开`。

每条有人声的镜，在代码块外补一行供 `release-gate` 装配规范取用：

```
🔊 音轨归属：🅐 模型生成 ｜ 台词全文"……" ｜ 绑定 2-6 秒 ｜ 预算 17字@4.5字/秒=4.2秒 ✅ ｜ 正文已写"口型与中文台词一致"
🔊 音轨归属：🅑 后期录制 ｜ 旁白全文"……" ｜ 占 2.6–6.6 秒（跨镜1→2）｜ 预算 11字+1破折号@3.3字/秒=4.0秒 ✅ ｜ 正文已写"无人声、无画外配音"
🔊 环境声钳制：正文已写"声音只使用{……}" ｜ 音乐：{不要背景音乐 / 已点单}
```

写完自检四步：①把每个代码块单独拎出来搜 `"` `“` `「`，每命中一处回答「它是 🅐 吗？过预算了吗？」；②搜 `旁白|广播|画外音|配音|独白|后录`，代码块**内**命中基本都是错；③搜同一句话是否在块内块外各出现一次；④**逐条确认第 ⑤ 段写了钳声或 BGM 点单，一条都不能漏**。

### 硬规则四：单镜素材容量预检

写完每一镜，对着该镜的素材清单核一遍 H3 全能参考的硬上限：

- 图片 ≤ 9 张
- 视频 ≤ 3 段，单段 2-15 秒，**总时长 ≤ 15 秒**
- 音频 ≤ 3 段，单段 2-15 秒，**必须配图片或视频，不能单独传**
- 图 + 视频 + 音频 **合计 ≤ 12 个文件**
- 单文件：视频 50MB / 图片 30MB / 音频 15MB

超限的镜必须当场处理：合并同类参考图、把长参考视频剪到 15 秒内、或把该镜拆成两条。**留到生成时才发现传不上去，整条要返工重写。**

## 剧情模式

当用户指定为「剧情模式」，或内容本身为连续剧情／剧本／多集叙事时，**自动启用**以下规则（叠加在基础规则之上）。剧情模式**默认走单镜模式**，因为需要逐镜验收与跨镜锚定。

### 场景连续性原则

**核心要求**：相邻分镜之间的空间必须存在合理的物理或叙事连接，禁止无交代地跳切到完全不同的地点。

1. **场景动线规划**（前置步骤）：写分镜之前先列出本集所有场景及其空间关系，规划角色在场景间的移动路线。
2. **同一空间内展开**：尽量让连续剧情发生在同一场景或相邻区域。
3. **过渡镜头**：必须转场时，用一个专门的过渡分镜交代空间移动（角色行走、镜头摇移到新地点、时间流逝蒙太奇）。

✅ 练剑场 → 练剑场旁的镇妖柱 ｜ ✅ 室内 → 推门走出 → 庭院 ｜ ❌ 练剑场 → 突然切到另一个庭院

### 角色台词与语音

剧情模式下角色**必须有台词**，但每一句先按硬规则三盖章再决定写在哪里。

- **🅐 台词**：绑定时间段、写明口型要求、过时长预算。示例：`3-6秒：苏小月瞪大眼睛，脱口而出："惹怒师兄？他会杀了我！"，口型与中文台词一致`
- **每句都要过预算**：一个 3 秒窗口只装得下约 11 个字。34 字的台词塞进 3 秒，模型只会加速吞字或截断——这是漫剧台词最常见的翻车方式。
- **🅑 台词**：品牌名／Slogan／必听信息一律 🅑。旁白／内心独白默认 🅑；仅在满足硬规则三的放宽三条件时可降级 🅐。
- **表演指导单列一段**，逐角色写语气与关系张力（H3 对这种写法响应很好）：`表演要求：真实短剧表演风格，不要夸张舞台腔。A 的语气是愤怒、委屈、急切的反驳；B 的语气是尖锐、强势、咄咄逼人的质问。两人之间有强烈对峙感，节奏逐步升级。`

### 信息增量申报（必填）

每个分镜在提示词代码块**之外**必须带一行申报，三选一（拍点定义与判定铁律见 `narrative-info-planner/references/beat-rhythm-rules.md`）：

```
📌 本镜信息增量：{观众从这一镜新知道了什么，用观众语言写} | 通道：{画面动作/台词/旁白/字幕} | 拍点：{信息拍/情绪拍}
📌 放大：挂靠 {I编号或"情绪拍-镜X"}（重复证明已送达的信息／延续已建立的情绪，只加强度不加新知）
📌 呼吸镜头（纯氛围/空间/留白）
```

1. 写成观众语言（「观众现在知道来访者是女儿」）；写不成观众语言的（「渲染孤独感」）归入放大或呼吸。**同一事实的第 2、3 次证明必须申报为放大，禁止编伪增量**。放大+呼吸合计不超过全片时长的 40%，不得连续三镜；放大挂靠的信息必须在其前 60 秒内送达过。
2. 上游若有 `{标题}-观众认知时间线.md`（narrative-info-planner 产物）或蓝图的「必须交代的信息」，逐条对号入座——每条枢纽信息都要能指出「落在哪一镜、走哪个通道」，落不下的就是设计漏洞，回上游解决，禁止顺手塞进旁白。
3. **枢纽事件**（杀人／背叛／相认／遗忘／决定）的信息增量通道必须是`画面动作`：事件本身要以可见的外部动作进入画面，台词／旁白只能补强。只拍反应镜不算拍了事件。
4. **旁白配额**：全片旁白承载的枢纽信息 ≤2 条，且仅限时空跳跃、画外前史这类画面与台词都无法自然承载的类型；旁白禁止转述同镜台词或解说画面正在演的动作。

### 叙事节奏

**解说漫剧例外**：若内容为名著解读／历史解说／知识叙事等解说体裁，**不使用下表**，改走 `narrative-info-planner/references/explainer-formula.md` 的悬念前置六步法，并按该文件的 K 卡清单列出全部后期卡字。

| 阶段 | 时长占比 | 作用 |
|------|---------|------|
| 开场 | 前 10-15% | 建立镜头 + 世界观/角色引入 |
| 铺垫 | 15-35% | 角色出场、情境建立、任务引入 |
| 发展 | 35-65% | 核心事件推进，角色互动与冲突 |
| 高潮 | 65-85% | 戏剧冲突爆发，视觉冲击最强 |
| 收尾 | 85-100% | 反转 + 情感落点 + 下集钩子 |

## 方位与服装的两条写法硬规则

> ⚠️ **硬规则：方位一律写「画面方位」，不写「人物方位」。**
> 写「铁钎在**他身体的右前方**，左前方是空的」会被理解反——人物面对镜头时，模型要先做一次镜像换算（人物的右＝画面的左），这一步经常出错。
> - ❌ `他的右手边放着水壶，左手边是空的`
> - ✅ `水壶在画面的左半边，画面右半边完全空着`
>
> 方位正反双写仍然要做（写清「在哪边」也写清「另一边是空的」），但**两端都用画面方位**。人物视角的方位只写在代码块外的说明行里给人看。
> **运镜方向同理**：「镜头向左横移」和「人物向左走」是两个坐标系，同一条提示词里混用必翻车——统一以画面为准，人物的运动方向也写成画面方向（如「人物从画面右侧走向画面左侧」）。

> ⚠️ **硬规则：服装写结构，不写品类词——品类词会自动带出制式细节。**
> 写「军绿色**双排扣**大衣」，模型会自动补一排铜扣、立领、军装剪裁，出来接近制式军大衣；在酒类、医药、金融等受管制品类的广告里，这会直接踩「不得变相使用军旗军徽」「不得使用国家机关工作人员形象」之类的红线。
> - ❌ `军绿色双排扣大衣`
> - ✅ `深藏青色厚棉大衣，金属拉链从下巴拉到腰部，拉链外盖一层同色门襟布，没有铜扣、没有双排扣、没有肩章臂章、没有任何徽章`，并补一句 `不是军装、不是制服、不是任何执法或公务人员着装`
>
> 同类雷区：军装、警服、白大褂、法官袍、校服。凡可能被读成「制服」的服装，都要在提示词里显式否定一次。

## 参考素材审计

当用户提供了角色／道具／场景的参考图清单时，在写分镜提示词**之前**执行：

### 第一步：逐分镜扫描

列出每个分镜中所有出场的视觉元素（角色、道具、场景、生物等），标注每个元素出现的分镜编号。

### 第二步：交叉比对

**问题 A — 素材缺口**：某个视觉元素在 **2 个或以上分镜**中出现，却没有对应的参考锚定图。没有参考图时 H3 每次随机生成该元素外观，跨分镜必然不一致。**必须标记为缺口**，并为该元素生成补充参考图的提示词（遵循原剧本的画风前缀与格式规范）。

⚠️ **「视觉元素」不止角色和道具**：复现的**氛围／环境主视觉**同样算——天空、云、天气奇观、标志性人海／群像、贯穿性特效、招牌地标。它们跨镜出现却各自随机生成，一样会穿帮，且最易被漏审。

**问题 B — 素材状态不匹配**：某参考图只覆盖了该元素的一种状态，但分镜需要另一种状态（完好 vs 碎裂、干净 vs 污染、日常 vs 觉醒）。必须在脚本中说明哪些分镜上传该图、哪些用纯文字描述另一状态。

**问题 C — 容量超限（H3 特有）**：逐镜核对硬规则四的上限，标出超限的镜与处理方案。

> ⚠️ **硬规则：每个分镜都必须有明确锚定，不得留「参考图：无」而无任何承接。** 每镜至少满足其一：①挂 `@图X` 参考图；②首尾帧承接相邻镜头（写明「首帧承接镜N尾帧」）；③挂 `@视频X` 锁人物／画风／节奏。
> - **一次性出场的符号角色／群演**也不能裸奔：挂一张环境／场景图作画风与环境锚（注明「仅锁环境画风与全局特效形态，人物为本镜一次性角色、不被参考图替换」）。
> - **纯氛围镜**（天空、烟云、空镜）用氛围锚定图或首尾帧链承接相邻镜。
> - 写完自检：通读每个分镜的锚定声明，确认**没有任何一镜是「参考图：无」且无首尾帧链、无视频锚**。

### 第三步：输出审计报告

在分镜脚本中插入「参考素材审计」章节：①原剧本提供的素材表 ②缺口列表（含严重程度：严重／轻微）③现有素材的适用性问题 ④容量超限清单与处理方案 ⑤补充素材的提示词（可直接用于生成锚定图）。

### 第四步：把补充素材真的生成出来

审计只输出提示词是**没做完**——缺口图不生成，跨镜一致性照样穿帮。审计报告写完后直接调用 `gpt-image-bridge` 生成补充锚定图，与原有素材放在同一目录：

```bash
~/.claude/skills/gpt-image-bridge/bin/gpt-image-2 \
  "<补充锚定图提示词全文>" \
  "<项目>/参考图/锚定-XXX.png" --size 1024x1536
```

- **锚定图不挂 `--ref`**——它本身就是基准，挂了会自我循环
- 生成后逐张过审计里列的判据，不过就重抽
- 生成完回到分镜提示词，把对应镜次的 `@图X` 编号与 `📎 上传顺序` 补上该图

若同一元素还要跨多张图保持一致（如同一角色的不同姿态、同一产品的不同角度），第二张起挂 `--ref` 指向第一张。参考图锁得住长相／服装／配色／画风，**锁不住构图与姿态**，那些仍要用文字写清楚。

## 画面内文字

**本技能允许 H3 模型直接绘制画面内文字（含中文）**——这与同族 seedance / vidu / hailuo / wanxiang 技能「一律后期卡字」的惯例不同，只在 H3 上放开。

凡分镜含标题、字幕、UI 文字、署名、落版字、招牌字，写提示词前读 [references/onscreen-text.md](references/onscreen-text.md)，按其五要素点单（内容／字体形态／颜色材质／动效／停留可读性），并在代码块外补一行 `🔤 画面内文字：…` 验收申报交给 `release-gate`。

**两条底线**：①品牌名／产品名／法务必现文案建议直接走后期——不是画不出，而是一个字错就整条素材作废且不可局部修，容错率为零；②长中文（>12 字）、手写体、密集排版无案例支撑，按 onscreen-text.md 的降级预案处理。

## 注意事项

- 单条输出 **4-15 秒**，24 FPS；单镜模式取 4-8 秒，序列模式取 10-15 秒。
- 提示词上限 **7000 字符**。
- **所有输出带声音**——每条都要钳声或点单，没有例外。
- H3 对短提示词执行力很好，简单动作不要过度堆砌（`固定镜头，机器臂下降，抓起红色方块，向前移动一段距离后放下` 就能work）。
- 涉及真人写实人脸时，跨镜一致性靠参考图 + 逐部件点名描述，不要指望模型记住。
- 远景不给正脸：`人物露脸只能是近景或特写，远景只能是背影、侧背或环境空镜，不要正脸远景`。
- 多语种版本：同一批参考素材 + 同一套画面描述，只换台词语言；音色一致靠给每个语种挂同一条 `@音频1`。
- 下游衔接：定稿后交 `storyboard-reviewer` 审片、交 `release-gate` 做装配规范与素材验收。
