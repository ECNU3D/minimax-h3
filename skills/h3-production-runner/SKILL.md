# 本地 H3 制片执行

先读 [生产入口](../../docs/h3-agent-production.md)。历史对话与 `archive/docs-copy/` 只作证据，不是启动说明。

## 唯一生成入口

生产任务只调用 `.venv-cu130/Scripts/python.exe scripts/h3_batch.py`，先离线预检，再加 `--execute`。
不要直接调用 `generate.py`、`/prompt`、临时 Python/PowerShell 循环绕开预算。不改执行脚本以让当前失败任务继续。
参考资产确实缺少时，按三白参考文档用已有图像流水线 `--until references` 生成一次，再锁定并复用；该入口不得用于绕开视频预算。

- `--campaign` 是本轮用户任务的固定 ID；修提示词、换 seed、换 run-dir、换集数均沿用本 campaign，不能自动另起预算。
- 同一逻辑镜头保持同一 name。旧式 `ep03_s07b/c/e` 归入 `ep03_s07`。
- 每镜最多 **2 次提交（首次 + 1 次重试/重做）**；批次 **3 次执行失败**，或某镜第二次执行仍失败，锁定 STOP。
- 执行成功但视觉不合格的重做也消耗提交额度。成功不是接受；写 `visual_status`，查看 contact sheet 和关键全尺寸帧。
- 退出码 `20` / `status=STOP`：立即输出失败摘要并结束当前 goal/turn。不得另起 goal、删 STOP/预算、改 campaign、改镜头名、无限“continue”。只有用户新的明确指令可以另开批次或调整预算。
- 默认一次等待 900 秒也会锁定 STOP（退出 20）；保留在途 prompt ID，不重提、不杀服务。兼容返回 `10` / `PENDING` 时也结束本轮等待，恢复只能使用原参数原目录。
- 其他非零：先分类。输入/路径/字体错误不值得跑 GPU；未知提交结果停止并对账；有明确 execution_error 的镜头在预算剩余时允许一次有理由的修订，用新 run-dir、同 campaign/name。

## 计划与检查

1. 先确定当前用户要求的集数/时长；不能把“优化流程”理解为续做全部剧集。
2. 精简为镜头清单、关键动作、参考顺序、风险和备用镜法。仅对新问题加载导演/节奏技能，不每集重写全部文档。
3. 先验证 1 个正常镜和最高风险镜，再继续全批。文字/UI 用后期；手部/倒影/纸张的本项目失败是风险提示，不是模型永远不能做的证明。
4. 默认恰好三张独立参考：人物白底、完整场景、道具白底，显式 `<Picture n>`。历史 EP2/3 的 1–3 图是例外；只有当前任务明确采用例外才加 `--allow-reference-override`，不能为了过预检自动加。
5. GPU 阶段串行。已运行任务先查队列和 prompt ID；禁止凭低 GPU 或日志静止判死锁、禁止每镜重启和模糊匹配杀 Python。
6. 已有角色/场景/道具按 SHA256 复用；生成成功从 job.json 的实际输出路径取片，禁止猜 `_00001_`。

列出采用镜头、输出哈希、执行/视觉状态、累计预算、未解决问题；失败需带 STOP 文件与下一步需用户决定的事项。
