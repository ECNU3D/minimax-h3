# 叙事短片剪辑

读 [剪辑与字幕规范](../../docs/video-editing-workflow.md)。用 `ffmpeg-skill` 执行裁切/拼接/字幕/混音，用已有 `remotion-best-practices` 处理真正需要 React 动效的包装。不要为了普通剪辑迁移渲染栈。

## 从素材开始

- 先读采用版本清单、实际音频时长，抽取每镜首/中/尾及剪点两侧。选素材中的有效动作区间，不能十条都 `tin=0` 再机械凑 90 秒。
- 每镜写一个观看目的：提供信息、人物反应、行动、空间建立。重复传递同一信息的空镜应缩短；呼吸镜仍需人物心理或节奏功能。
- 音频先做粗排再锁剪点。可用 J-cut（先听后见）/L-cut（切画面保留尾音）连接对白与反应；关键台词、音效和尾音不能因镜头长度被切断。
- 叙事画面默认硬切；只在时间/空间变化需要时加转场，不把转场特效当成剪辑质量。
- 给每条 EDL 记录 `source/path/hash, in, out, timeline_in, purpose, accepted_variant`；另外保留采用依据及替换代价。总时长按实际帧数核算。

## 执行

剪辑导演台交接包时，先读取 `edit-manifest.json` 的 `delivery` 字段，按其中的项目名/日期目录输出成片、声音、字幕、剪辑工程和验收材料。旧包缺少此字段时，默认使用仓库 `成片/<项目名>/<日期时间>/`，不要用包 ID 或任务 hash 作为用户交付目录。成片放 `视频/`，文件名带片名和版本；保留已有版本，完成后写 `交付清单.md` 并给用户实际成片的绝对路径链接。

在仓库根目录调用 `scripts/run_ffmpeg_skill.ps1`，具体参数从工具 `--help` 取得。
长编码先 `--dry-run --json`；三步以上用该技能 project.json 流程。查第三方 skill 的精确格式，不凭记忆发明 schema。

- 缩放保留宽高比。裁切后补边或重新构图，不能把 1170×768 强拉成 1344×768 并称“等比”。
- 明确哪些字是对白/旁白字幕、哪些是画内道具文字、哪些是信息卡。画面里已有可读文字时避免重复压字；贴进透视屏幕必须跟踪，做不到就明确做独立卡。
- 音轨使用真实 transcript，角色母版复用。剪辑任务包含本地配音/配乐时，先用仓库 `skills/local-film-audio/SKILL.md` 补齐配音、音效、音乐并校准字幕；“后期录制”是待执行工序，不是等待用户提供录音。必要对白仍生成失败才报告阻塞，不允许静默跳过后宣称完成。
- 混音先平衡对白、环境、音乐，再测 LUFS/真峰值。数值合格不代表听感合格，抽听对白密集段及转场；未听就写未听。
- 改字幕需要从干净源镜头重建画面；不能在已硬烧字幕的成片上再叠一层。只换音轨时才 stream-copy 视频并验证流哈希。

## 交付门槛

调用 `subtitle-layout-qa`，发布前沿用已有 `release-gate`。最终成片检查格式、全片解码、字幕最长句与跨镜处、首尾/转场、音轨缺失、台词可懂性。
分别报告技术验收、视觉审查、听音与用户接受状态。保持源素材与旧成片，交付新版本和剪辑表。
